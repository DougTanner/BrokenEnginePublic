# `DataPacker/Source`

Asset preprocessing tool that converts raw assets (textures, models, shaders, audio) into optimized binary formats for runtime loading.

## Architecture

Main.cpp orchestrates a multi-phase pipeline: a one-shot migration of legacy `.BC[457]_UNORM_BLOCK` / `.R16_UNORM` intermediates to the current magic-prefixed format (idempotent via the `kiTextureIntermediateMagic` byte-0 check; BCn files get a full decode → re-encode with current RDO knobs, R16 a zlib wrap), then pre-export (Scene, a Gaea bake of island intermediates, Islands) generates intermediates, offline IBL cubemap convolution runs next, main export processes the remaining asset types (every type runs even if an earlier one failed; each type's job failures combine into one MessageBox), then header generation and ThirdParty attribution collection. The Gaea bake is a separate step (not an `ExportJob`) that shells out to `Gaea.Swarm.exe` once per dirty route per island, parses the resulting heightmap / textures / mesh, and splits each into per-chunk leaves in the shared cache. The bake/split orchestration — route table, archetype patching, elevation scaling, auto-crop, mesh subdivision — is documented in the two paragraphs below (the bake TUs live in `ExportJobs/Island/`); cache ownership, the two-stage dirty sentinels, leaf rejection, and the `ExportIsland` chunk consumer are documented in `ExportJobs/AGENTS.md`.

Files split for eventual Gaea 3 migration (all in `ExportJobs/Island/`): all Gaea-version-specific logic (executable resolution, archetype patching, Sea-level read) is confined to `GaeaArchetype.{h,cpp}`. The version-agnostic bake/split orchestration spans three TUs sharing the private `BakeIslandIntermediatesInternal.h` (bake-context structs, shared constants, the two cross-TU forward declarations): `BakeIslandIntermediates.cpp` (top-level entry point and route-table resolution), `BakeRoute.cpp` (one route's two-stage Gaea bake plus split), and `ProcessBakedRegion.cpp` (per-region crop / downsample / leaf write). `SubdivideBeachBand.{h,cpp}` is a fourth, self-contained TU: adaptive shoreline mesh densification run once on the full route mesh before the per-region split — triangles straddling beach Z subdivide until shoreline XY edges drop to ≤ 1 m, while out-of-band neighbours absorb shared midpoints without creating new ones so the cascade dies one ring outside the band. `GaeaArchetype.h` is deliberately json-free, so `Island.json → archetype path` resolution (which takes a parsed `nlohmann::json`) stays in `BakeIslandIntermediates.cpp`. The source `.terrain` is never mutated: each route copies and patches it in `%TEMP%/DataPacker/<project>/Gaea/Islands/...` before invoking `Gaea.Swarm.exe`, so sibling routes/islands sharing an archetype never collide and a crashed process cannot leave a half-patched source.

The elevation pipeline is meters-absolute end-to-end. Gaea emits float-raw normalized elevation; DataPacker reads (never writes) the archetype's Sea node `Level` (`ReadArchetypeSeaLevel`, falling back to `kfGaeaSeaLevelDefault = 0.1f` when absent), scales by `Island.json`'s `elevationMeters`, and offsets by `fBeachOffsetMeters = Level × elevationMeters` so engine-Z 0 is the beach, water is negative down to `-fBeachOffsetMeters` (the sea floor), land positive. Because `Level` is read rather than mutated, Gaea's editor preview and the in-game water surface agree. The engine pins the sea floor to a single global `common::kfSeaBottomMeters` (-10 m); DataPacker asserts each bake's `-fBeachOffsetMeters` matches it within 0.01 m, so all shipping islands run `elevationMeters = 100` at Level 0.1 — changing either side requires moving `kfSeaBottomMeters` in lockstep. Auto-crop trims only the deepest water: a pixel is kept when its elevation exceeds `seaFloor + kfCropEpsilonAboveSeaFloorMeters` (1 m above the sea floor, i.e. a cut line near -9 m), preserving the whole landmass plus a shallow-water coastline halo. The bake throws if `fBeachOffsetMeters <= kfCropEpsilonAboveSeaFloorMeters` (the cut line would reach sea level and strip the halo). The runtime samples elevation directly with no per-island height or water-depth multipliers.

Single-instance guard is a named Win32 mutex; a second instance waits for the first to finish rather than exiting (build events can stack). Outside the debugger, top-level `try/catch` shows a MessageBox; under the debugger it runs unwrapped so exceptions break in. Three diagnostic CLI modes (`--rdo-sweep`, `--rdo-sweep-full`, `--rdo-sweep-validate`, each taking one image/intermediate path) short-circuit the normal run to profile BC7 RDO lambda / lookback / uber knobs and emit a Pareto frontier — used only when retuning the encoder constants in `Texture.cpp` (`main` only dispatches them; the sweep itself lives beside that encoder in `ExportJobs/Texture/RdoSweep.{h,cpp}`).

FileManager (`gpFileManager`) owns input/output/temp directory resolution, ThirdParty-directory resolution (derived from the canonical engine-data input dir), and CLI parsing; `mOutputDirectory` is canonicalized to an absolute path. `%TEMP%/DataPacker/<project>` is shared across worktrees and holds export chunks, fingerprint metadata, and the single mutable `Gaea/` cache. Input fingerprints use Git blob IDs for unchanged tracked files and content hashes for modified, ignored, generated, or non-Git files; directory fingerprints sort relative child paths before combining them. CLI accepts zero args (sandbox defaults) or exactly three (engine-data, project-data, output-dir). `mbCleanExport` forces a full re-export but nothing sets it — no CLI flag exists; it is a debugger/code-edit-only toggle. Vulkan SDK path lookup (`VK_SDK_PATH` + `Bin/` required for glslc / glslangValidator / spirv-opt) is local to the shader exporter's TU. ThirdParty license collection is a free function called from `Main.cpp` post-export, sourcing the ThirdParty directory from `gpFileManager`.

Worktree builds have two data modes. Shared consumes the primary checkout's complete generated output. Local is mandatory for DataPacker source, asset input, generated-header, compression, chunk-layout, or pack/manifest contract changes and consumes complete worktree-local `Output/Data` prepared for the current changes. Game projects detect the canonical repository-root `.git`: a linked worktree's file defaults `RunDataPacker=false`, while the primary checkout's directory preserves automatic Local Visual Studio export. Explicit Local true permits deliberate worktree generation and incrementally rebuilds Release DataPacker before export; Shared rejects true. Missing or stale Local output fails without fallback, and an export must never write into the primary checkout or copy worktree source changes there for testing.

`Texture` (`ExportJobs/Texture/Texture.{h,cpp}`, beside the `MigrateLegacyIntermediates.{h,cpp}` startup-migration pass) loads (EXR / PNG / raw float / raw uint16), mip-generates, and encodes to BC4/5/7 plus uncompressed R8G8B8A8/R16/R32_SFLOAT, keeping internal pixels as RGBA float at 0–255 scale (not 0..1). BC mip chains terminate once width or height drops below 4 or stops being divisible by 4. BC7 RDO knobs (lambda / lookback window / uber level) are tuned constants at the top of `Texture.cpp`; the RDO encoder internally spawns `HardwareCoreCount() - 2` threads (two physical cores left idle for the OS), so callers serialize whole construct→mip→encode chains behind the static `sEncodeMutex` to bound peak memory. No PNG/EXR writer is wired up (load-only for those formats), so `ExportIsland` crops full-res Color/Normals in-memory rather than re-staging them on disk; JPEG sidecars are a debug-visualization path only. `Texture.h` also declares four shared free functions used across export TUs: `ZlibCompress` (shared by texture-intermediate writers and the RDO sweep), `HasCubemapTag` (tests whether a filename carries the `[C]` cubemap tag; shared by `ExportTexture` routing and `ExportCubemapIbl`), `TextureIntermediateSuffix` (canonical `VkFormat`→intermediate filename suffix for all five intermediate formats; used by `ExportScene`, `MigrateLegacyIntermediates`, `ExportTexture`, `ExportCubemapIbl`, and `ExportIsland`), and `ReadTextureIntermediateHeader` (parses the optional `kiTextureIntermediateMagic` prefix and the width/height/mipcount `int64_t` qwords with legacy tolerance; shared by `ExportTexture`, `RdoSweep`, and `MigrateLegacyIntermediates` — each caller applies its own error policy).

Pch.h's log categories default to `kVerbose`. Tools builds have no allocation tracker (see `Engine/Source/Memory/AGENTS.md`), so the engine's LOG float-format-spec ban does not apply here — `{:4.2f}`-style specs in `LOG(...)` are fine.

## Design Patterns

- **Template-based processing**: `RunExportJobs<T>()` provides type-safe job management with dirty checking, constrained by the `IsExportJob` concept (requires `kName`, `Handles()`, and `ExportJob` derivation). Aggregate `.pack` / `.manifest` validity is independent of per-job chunk validity: missing outputs and manifest version/job-count mismatches trigger aggregate regeneration, which reuses every clean shared chunk. After the relative-path sort, an adjacent-pair walk throws `std::runtime_error` if two jobs share a case-folded relative path, catching the silent two-input-root collision (same relative path under engine `Data` and project `Data` would produce duplicate manifest CRC entries and duplicate generated constants). Parallelism is one `std::async` task per matched asset — no central thread pool. `T::Handles(entry)` returns `std::optional<ChunkFlags_t>` to accept-and-tag.
- **Atomic writes**: Outputs written to temp directory first, renamed on success. On any job failure, temp files removed and run returns non-zero without touching prior outputs.
- **Content-based updates**: Generated headers only overwritten when content differs, preventing unnecessary recompilation.
- **Deterministic output**: Assets sorted by relative path before processing for consistent chunk *ordering* (byte-level reproducibility is per-bake-host — see Cross-Machine Reproducibility below).

## Cross-Machine Reproducibility

Chunk *ordering* is machine-independent — assets are sorted by `common::ToLower(mRelativeFile)` before processing, with an adjacent-pair uniqueness guard so `std::sort` has no tied keys (`Main.cpp`, serving the "stable bytes for efficient Steam patching" goal). Chunk *bytes*, by contrast, are reproducible only **per bake host** along three paths. This is acceptable under the **single-canonical-bake-machine assumption**: all shipping packs are baked on one machine, so cross-host variance never materializes. If CI / multi-developer bakes are ever introduced, pin each path (the knob sites carry matching comments):

- **BC7 RDO encode** (`ExportJobs/Texture/Texture.cpp`, `EncodeWithRdo`): `m_rdo_max_threads = HardwareCoreCount() - 2` with `m_rdo_multithreading = true`. bc7enc_rdo's ERT partitions the block stream into per-thread contiguous ranges and matches cannot cross partitions, so encoded BCn bytes vary with core count. Fix: pin `m_rdo_max_threads` to a fixed constant (bounded encode-time cost — whole-texture encodes already serialize behind `sEncodeMutex`).
- **IBL radiance convolution** (`ExportJobs/ExportCubemapIbl.cpp`, `GeneratePreFilteredCubemaps`): runs on whatever OpenCL GPU is present (`clInit(CMFT_CL_VENDOR_ANY_GPU, …)`), so the pre-filtered half-floats are GPU/driver-dependent; the CPU fallback's thread count comes from `hardware_concurrency`. Fix: force a pinned-thread CPU path (significantly slower convolution). The sibling SH *irradiance* path (`imageIrradianceFilterSh`) is serial CPU with no OpenCL/thread input — only generic FP-environment exposure (DataPacker is not `/fp:strict`), so its cross-host variance risk is low.
- **Gaea island bake** (`Gaea.Swarm.exe`, via `ExportJobs/Island/GaeaArchetype.{h,cpp}`): seeds are patched per-route and `--seed` dropped, so the bake is fully input-determined *at the DataPacker layer*, but Gaea itself is GPU-accelerated and may not produce byte-identical heightmaps/colors across GPUs/drivers — the largest *practical* cross-host variance in the island pipeline. It is upstream of all first-party byte-emitting code; treat it like a source asset that must come from the canonical host.

## Output Structure

Each asset type produces `.manifest` (CRC-to-chunk-location), `.pack` (binary data), `.h` (C++ CRC constants). Also generates `DataTypes.h` (enum/names only), `Data.h` (aggregates CRC headers), and sibling `Attribution/` directory. Split headers let files needing only the enum avoid recompilation when asset CRCs change.

Manifest layout: `common::DataHeader` then aligned array of `common::ChunkLocation`. Attribution: `<output-parent>/Attribution/<LibraryName>/`; license search matches exact lowercase `license` / `license.md` / `license.txt`, falling back to names containing `copying`/`readme` or exactly `manual.md`. `Prebuilts` skipped; a ThirdParty dir with no recognizable license ASSERTs.
