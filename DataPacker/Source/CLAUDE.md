# `DataPacker/Source`

Asset preprocessing tool that converts raw assets (textures, models, shaders, audio, fonts) into optimized binary formats for runtime loading.

## Architecture

Main.cpp orchestrates a multi-phase pipeline: a one-shot legacy-raw → zlib migration of `.BC[457]_UNORM_BLOCK` / `.R16_UNORM` intermediates (idempotent: skips files whose payload size doesn't match raw-size math), then pre-export (Scene, a Gaea bake of island intermediates, Islands) generates intermediates, offline IBL cubemap convolution runs next, main export processes asset types in parallel, then header generation and ThirdParty attribution collection. The Gaea bake is a separate step (not an `ExportJob`) that shells out to `Gaea.Swarm.exe` once per route per island (an island declares one or more routes; see `ExportJobs/CLAUDE.md`) at the requested texture resolution. All Gaea-version-specific logic (executable resolution, archetype patching, Sea-level read) is confined to `GaeaArchetype.{h,cpp}` for easier migration; `BakeIslandIntermediates.cpp` keeps the version-agnostic bake/split orchestration. The `GaeaArchetype.h` header is deliberately json-free, so `Island.json → archetype path` resolution (which takes a parsed `nlohmann::json`) stays in `BakeIslandIntermediates.cpp`. The Mesher's `Mesh.gltf` is then run through an adaptive beach-band densification pass: triangles straddling the shoreline are recursively midpoint-subdivided until the longest XY edge meets a fixed engine-meters target, and out-of-band one-ring neighbors absorb the new midpoints via minimal T-junction splits that introduce no further midpoints. The elevation pipeline is meters-absolute end-to-end: Gaea emits float-raw normalized elevation, DataPacker reads the archetype's Sea node `Level` (via `ReadArchetypeSeaLevel`, falling back to `kfGaeaSeaLevelDefault = 0.1f` when absent), then scales by Island.json's `elevationMeters` (also patched into the archetype's `Terrain.Height` before the bake) and subtracts a per-bake `fBeachOffsetMeters = fSeaLevelNormalized * elevationMeters` so pixel value 0 means sea level (beach). The Sea node `Level` is NEVER mutated by DataPacker — Gaea's editor preview and the in-game terrain agree on the water surface position. Sea node `ShoreHeight` is likewise untouched (it drives Gaea's shoreline visual effects only). Sea floor depth scales with `elevationMeters`, but the engine pins it to a single global value via `common::kfSeaBottomMeters` (-10 m). DataPacker asserts each bake's `-fBeachOffsetMeters` matches that constant within 0.01 m, so all shipping islands currently run with `elevationMeters=100` at Level 0.1. Changing either side requires raising `kfSeaBottomMeters` in lockstep. The meter-elevation buffer is scanned for the bbox of pixels above the crop epsilon (1.0 m), the bbox is expanded symmetrically to a multiple of `4 × kiElevationDivisor` in each axis, and elevation + AO are cropped to that anisotropic rect (Color PNG and Normals EXR stay full-res on disk in the route's `Intermediates/` and are cropped in-memory per chunk at `ExportIsland` time). Color is baked as 8-bit sRGB PNG (loaded via stb_image, treated as already-encoded gamma values — no second gamma pass) and Normals as float EXR (loaded linear; direction vectors are not gamma-encoded). Elevation is then box-filter downsampled in-process by `kiElevationDivisor` and the heightmap is written as R32_SFLOAT meters; each chunk leaf's `Intermediates/BakedDimensions.json` records the post-crop world width / height, the source crop rect, and a leaf-relative `textureSourceDir` pointing at the route's shared full-res sources. Leaves whose downsampled peak is below `kfMinIslandMaxHeightMeters` are deleted at split time (no leaf, no chunk — leaf indices can be sparse). Two route-level sentinels gate re-baking: `BakeVersion.txt` (the slow Gaea raw stage) and `SplitVersion.txt` (the fast post-Gaea split, stamped last after every leaf) — so a split-only change re-splits the existing bake without re-running `Gaea.Swarm`. (Elevation is sampled by a vertex grid in `Terrain.vert` and doesn't need per-texel resolution; the auto-crop combined with the downsample is the primary disk-size lever for islands.) The runtime samples directly with no per-island height or water-depth multipliers. The on-disk archetype `.terrain` is never mutated. Each route's bake copies the source to `<island>/<route>/Intermediates/PatchedArchetype.terrain`, patches the copy, and hands that path to `Gaea.Swarm.exe --Filename`. No cross-process lock or RAII restore is needed — sibling routes/islands sharing an archetype each work in their own `Intermediates/` directory, and a crashed process can't leave the source in a half-patched state. The patched copy doubles as a debug artifact (open in Gaea to inspect exactly what was fed to the bake). The patch covers archetype dimensions, the archetype's single Gaea `Route` node `Choice` (the per-route subdivision selector), every per-node `"Seed"` field (Gaea's `--seed` CLI flag only mixes a global seed into per-node randomness, so per-node fields must be overwritten directly; `"seed": 0` in `Island.json` is the "use archetype seeds as authored" sentinel and skips the per-node overwrite entirely, so you can A/B against Gaea's editor preview), and (optionally) `Mesher.VerticesPerSide`. Single-instance guard is a named Win32 mutex. Outside the debugger, top-level `try/catch` shows a MessageBox; under the debugger it runs unwrapped so exceptions break in.

FileManager (`gpFileManager`) owns input/output/temp directory resolution and CLI parsing only. CLI accepts zero args (sandbox defaults) or exactly three (engine-data, project-data, output-dir). Vulkan SDK path lookup (`VK_SDK_PATH` + `Bin/` required for glslc / glslangValidator / spirv-opt) is local to the shader exporter's TU. ThirdParty license collection is a free function called from `Main.cpp` post-export.

Texture utilities keep internal pixels as RGBA float at 0–255 scale (not 0..1). BC4/BC5/BC7 mip chains terminate once width or height drops below 4 or stops being divisible by 4.

Pch.h sets `kbIsDataPacker = true` (distinct from engine/game PCH); log categories default to `kVerbose`.

## Design Patterns

- **Template-based processing**: `RunExportJobs<T>()` provides type-safe job management with dirty checking, constrained by the `IsExportJob` concept (requires `kName`, `Handles()`, and `ExportJob` derivation). Parallelism is one `std::async` task per matched asset — no central thread pool. `T::Handles(entry)` returns `std::optional<ChunkFlags_t>` to accept-and-tag.
- **Atomic writes**: Outputs written to temp directory first, renamed on success. On any job failure, temp files removed and run returns non-zero without touching prior outputs.
- **Content-based updates**: Generated headers only overwritten when content differs, preventing unnecessary recompilation.
- **Deterministic output**: Assets sorted by relative path before processing for consistent chunk ordering.

## Output Structure

Each asset type produces `.manifest` (CRC-to-chunk-location), `.pack` (binary data), `.h` (C++ CRC constants). Also generates `DataTypes.h` (enum/names only), `Data.h` (aggregates CRC headers), and sibling `Attribution/` directory. Split headers let files needing only the enum avoid recompilation when asset CRCs change.

Manifest layout: `common::DataHeader` then aligned array of `common::ChunkLocation`. Attribution: `<output-parent>/Attribution/<LibraryName>/`; license search tries `LICENSE*` then `copying*` / `readme*` / `manual.md`. `Prebuilts` skipped; a ThirdParty dir with no recognizable license ASSERTs.
