### H001 — Replay recording start continues after grid snapshot failure

- Location: `Projects/BrokenEngineSandbox/Source/Save/GameSaveLoad.cpp:304-312`
- Label: Oversight
- Sameness: Related
- Confidence: high
- Matching pattern: `WriteGrid(...)` at line 304 is one of the plan's acknowledged void-context callers. Once the plan changes `WriteGrid` to return the atomic-write result, this call will have an available failure result but is explicitly slated to discard it. The code then creates `mReplayWriters` for every active coord and logs `Recording started for {} coords` at line 312.
- Justification: `F7.replay.grid` is required by playback (`GameSaveLoad.cpp:232-238` calls `ReadGrid` and aborts if it cannot read the file). If its initial write fails, starting writers and publishing the start log leaves a recording that cannot later load. The same failure-threading intent applies, but the exact handling is a related edit: consume the new `WriteGrid` result and abort recording start (with a failure log) rather than forwarding it through `ServerSave`/agent dispatch.
- History: `git blame` attributes the start path and `WriteGrid` call to commits dated March-May 2026, while the plan was introduced by `89f70e0e7246b07483db64f1b33e9048b28a89b2` on 2026-07-09. It existed when the plan was written.

### H002 — Replay recording stop discards component write failures then logs stopped

- Location: `Projects/BrokenEngineSandbox/Source/Save/GameSaveLoad.cpp:322-361`; supporting captured results in `Engine/Source/File/DifferenceStream.h:68-165`
- Label: Oversight
- Sameness: Related
- Confidence: medium
- Matching pattern: the replay manifest's `WriteFileAtomically` result is explicitly discarded at line 322; replay metadata's `WriteVersionedFile` result is discarded at line 359; each `DifferenceStreamWriter::Save` call at line 348 returns `void` even though its implementation captures `bHeaderWritten`, `bFramesWritten`, `bChecksumsWritten`, and optional `bFullFramesWritten` and detects failure. The stop path clears all writers and unconditionally logs `Recording stopped` at line 361.
- Justification: a failure in any required replay component produces an incomplete/unloadable recording while the operation still reaches its normal completion log. This matches the plan's caller-observable false-success intent. It is Related rather than Identical because a complete fix must aggregate several sibling-file outcomes and likely change `DifferenceStreamWriter::Save` to expose its already-computed success state; that is a wider mechanical ripple than returning `WriteGrid`'s single `bool`. Confidence is medium because `Recording stopped` literally describes the state transition even on persistence failure, but in this save workflow it is also the only normal completion signal and follows required persistence work.
- History: `git blame` shows the stop flow, discarded manifest result, metadata write, and completion log were present by May 2026; the plan was introduced on 2026-07-09. Post-plan changes to `DifferenceStream.h` only revised frame serialization/read validation and did not create this failure-reporting pattern.
