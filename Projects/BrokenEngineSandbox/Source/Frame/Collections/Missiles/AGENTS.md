# /Projects/BrokenEngineSandbox/Source/Frame/Collections/Missiles/

Guided homing missiles with area-of-effect damage. Each missile owns a client-only area light, smoke trail, and sound.

## Game-Specific Behavior

- **Two-phase homing**: An initial boost ramps rotation strength from zero to full over a short delay; active tracking then orients toward the target with exponential smoothing. Targetless missiles orient toward the stored direction and re-attempt acquisition every Tick via `Frame::GetMissileTarget` (same path used at spawn); homing on a freshly-acquired target engages the next Tick to match the read-previous / write-current pattern. The boost-ramp delay is preserved across re-acquisition (no spawn-style soft launch on re-target).
- **Area damage model**: Missiles deal zero direct collision damage — all damage flows through the single AoE explosion registered in Explode, using the constant radius/damage from `HealthDamage.h`. Collision always registers per-element damage 0; exploding entries use `kAlreadyCollided` (stay in the layer without hitting anything during the death animation), others `kDestroyOnCollide`.
- **Earliest impact resolution**: A live missile resolves one earliest event across swept entity collision, point-swept terrain impact, and frame-boundary transfer. Entity and terrain impacts move the missile to the resolved position before explosion and trail sync; terrain and boundary events win exact-time ties through the collision layer's exclusive cutoff.
- **Target subscription lifetime**: Each Update tick must verify the target still exists in the Targets id map and still carries the destination flag. On either failure, release the subscription (only possible when the target row still exists), clear the id, and snapshot the current direction as the fallback orientation. Transfer/Destroy release the subscription only if the target still exists.
- **Explode is idempotent**: Guarded by a `kExploding` early-out. Plays a client one-shot explosion sound, spawns three simultaneous explosions (full/half/quarter scale, position jitter on the smaller two), registers AoE via `engine::AreaDamage::Add`, removes area light and looping sound immediately — smoke trail persists through the destroy animation. Directional (terrain) hits sample the cell's terrain normal for hemispherical trail/particle spread.
- **AreaDamage() phase is intentionally empty**: AoE registration happens inside Explode at hit time (PostCollision). The phase exists only to satisfy the collection interface.
- **Destroyed-time sentinel**: `-1` = alive, `> 0` = death-animation countdown (decayed in Interpolate Update, scales render size), `0` = finished — render skips the entry and Destroy removes it.
- **Static-at-spawn fields** (the unconditional-store exception noted at the [Collections hub](../AGENTS.md)): Flags, explosion direction, delta-rotation-max, acceleration, pitch, alignment (and sounds on client) are `memcpy`'d in `AllocateAndCopy` and not re-stored by Update. Mutated only at state transitions: Explode (flags, explosion direction, sound release) and PostCollision's transfer flagging.
- **Client-only consumers, shared RNG**: Pitch (spawn-time) and exhaust length (re-randomized every PostRender tick) feed only client audio/visuals but live in `SharedMembers()` (CRC'd) and draw from the shared frame random engine — both builds must draw identically, so their tuning constants stay `constexpr`, never runtime-tweakable.
- **Smoke-trail reuse across cell transfer**: The smoke-trail id is carried in `TransferData` so the destination cell re-binds the existing visual trail via `ClientInit`. Area lights and sounds are re-created fresh on arrival.
- **Engine sound + muzzle one-shot**: Each missile carries one looping engine voice on the Sounds collection (synced to the missile each frame via `Sync`). The launch cue is a fire-and-forget `gpAudioManager->PlayOneShot3d` fired once at the muzzle in `PlayersPostRender::SpawnMissiles` (Players/PlayersCombat.cpp) — not tracked in the Sounds collection, so cross-cell `TransferRequest` re-spawns do not retrigger it.
