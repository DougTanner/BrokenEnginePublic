# `/Network/` - Client and Server Sessions

## Overview

Game-level networking sessions that inherit from engine base classes and encapsulate all multiplayer orchestration. Separates networking concerns from the core Game coordinator. Each session is conditionally compiled (`BT_CLIENT` / `BT_SERVER`) and owned by Game via `unique_ptr`.

## Key Classes

- **ClientSession** (`game::gpClientSession`, `#ifdef BT_CLIENT`) - Inherits `engine::ClientSessionBase`. Handles connection lifecycle, player event processing (assigned/spawned/changed-frame/died), full-state application, subscription management, clock correction, desync detection/recovery, and `ResetForServerLoad()` (clears player identities, coord slots, buffered frames, and reconciler state on `kServerLoadNotification`). Split across companion `.cpp` files by responsibility (core, subscriptions). Delegates reconciliation to `ClientReconciler`
- **ClientReconciler** - Rollback-and-replay reconciliation on a dedicated `PersistentWorker` thread. Owns `ReconcileContext` and snapshot state swapped from `CoordFrames` at kick time. Re-syncs human identity from `gpGame` at `Kick()` time. `ConfirmedHumanState` carries both the human grid coord and the human `global_player_t` so that reconciliation can match the focused player by stable identity rather than local index. Parallelizes per-coord work via an owned `Multithreading` dispatch pool, controlled by `kbReconcileDispatch` in `Pch.h`. Merges per-coord `ReconcileProfiling` counters into the aggregate context after the dispatch join. At writeback, captures any human player position delta as a visual error offset on `gpGame`, allowing the camera to smoothly absorb reconciliation corrections without affecting the authoritative simulation position
- **ReconcileReplay** (`ReconcileReplay.h` + 3 `.cpp` files) - Stateless pipeline helpers for rollback reconciliation. CRC fast-path skips replay when client snapshots match shared CRCs. Full path: rollback to confirmed frame, replay server-validated ticks with StatusChange injection, catch-up to target tick. Pending full states are injected at the matching tick during replay. Neighbor coord CRC mismatches are non-fatal; only the human coord CRC mismatch triggers desync. `ReconcileReplayCoord` applies an adaptive replay throttle using `iJitterUs` from `ReconcileContext`: low jitter (<=2ms) allows full replay, medium jitter uses half, high jitter (>=8ms) uses quarter. A gap-aware override bypasses the jitter throttle when the confirmed-to-target gap exceeds half the ring buffer, allowing replay up to 3/4 of ring buffer capacity to prevent cascading failure from growing backlogs. `ReconcileCatchUpCoord` caps catch-up ticks to the remaining ring buffer budget, stopping gracefully instead of hitting the ring buffer full path
- **ServerSession** (`game::gpServerSession`, `#ifdef BT_SERVER`) - Inherits `engine::ServerSessionBase`. Manages active set computation, tick broadcasting, client spawn/disconnect lifecycle, player death detection, cross-cell transfer harvesting, subscription updates (using `SubscriptionUpdate` structs that carry a `global_player_t` to track which player triggered a coord change), resync request handling, weapon mode request processing (`ProcessWeaponModeRequests` drains `PendingWeaponModeRequest`s — each carrying a `global_player_t` — and injects `kWeaponModeChange` StatusChanges in `BuildFrameInputs`; pending requests are also cleared in `ResetClientsForLoad`), and `ResetClientsForLoad()` (broadcasts load notification, re-links clients to players by GUID matching `pClientGuids`, clears pending spawns/disconnects). Players persist in the game world on client disconnect (no destroy injected); on reconnect, `FinalizeNewClients` re-links the client to its surviving players by matching `ClientGuid` against `pClientGuids`. `ComputeActiveSet` activates only frames that are subscribed, contain players, have pending destroys, or are the origin coord; `EnsurePlayerCoords` and `EnsureDestroyCoords` helpers enforce the player and pending-destroy constraints respectively. `CollectTransfers` creates destination frames on demand so no transfers are dropped. `PrepareTick` skips `ComputeActiveSet` during replay (`gpGame->mGameSaveLoad.IsReplaying()`) so that the active coord set populated by `PrepareActiveSet` from the reader map is preserved unchanged each tick
- **PlayerEvents** (`PlayerEvents.h/.cpp`) - Game-layer parsing of raw game packets. Defines `PlayerEventType`, `PlayerStateWireType` for wire encoding, and `ReceivedPlayerEvent` (which carries a `global_player_t` instead of a local player index). `ParsePlayerEvents()` converts raw packet bytes into typed events
- **NetworkSerialization** (`NetworkSerialization.cpp`) - Game-layer implementation of `engine::NetworkSerialization.h`. Binary serialization of `StatusChange` batches with type-grouped encoding and LZ4 compress/decompress variants

## Architecture Notes

- **ClientSession companion files**: `ClientSession.cpp` (core/reconcile integration), `ClientSessionSubscriptions.cpp` (coord subscription management via `UpdateDesiredCoords()` called at player event points, death screen handling, full-state application)
- **ReconcileReplay companion files**: `ReconcileReplay.cpp` (core replay pipeline and adaptive throttle), `ReconcileReplayCrc.cpp` (CRC fast-path validation), `ReconcileReplayHumanState.cpp` (human state tracking across replay ticks)
- **Sticky subscriptions**: When coords drop out of the desired set, they remain active for `kStickySubscriptionDuration` (2 s) via `mUnwantedTimestamps`. `UpdateSubscriptions()` merges unexpired timestamps into the effective list before unsubscribing, preventing flicker during brief coord transitions
- **Soft desync recovery**: On CRC mismatch, client sends `kClientResyncRequest` instead of disconnecting. Server tears down and re-sends full state. Client tracks desync frequency and escalates to disconnect after 3 desyncs within 10 seconds
- **Full state tick validation**: Full states received for a coord with existing confirmed state are rejected at receive time if their tick is at or before the confirmed tick. Unconsumed pending full states are preserved across reconcile passes (written back to `CoordFrames` in `ApplyCoordWriteback` and on desync path). At reconcile time, stale pending full states (tick before confirmed) are discarded; states at the confirmed tick are injected as the rollback base; states matching a later tick during replay are injected mid-replay
- **ReconcileProfiling**: Standalone struct (defined in `ClientReconciler.h`) holding tick and event counters for one coord's reconcile pass. Embedded in both `CoordReconcileWork` (per-coord) and `ReconcileContext` (aggregate, via `Profiling` type alias)
