# `/Engine/Source/Audio/`

3D spatial audio via DirectXTK `AudioEngine` (XAudio2 wrapper). Global: `gpAudioManager`. Client-only (see hub for the `BT_CLIENT` convention).

## Key Classes

- **AudioManager** - XAudio2 device lifecycle, focus/suspend, device-reset callbacks. Constructor enumerates render endpoints to bind the OS default (falls back to first active), enables the mastering limiter, and caches the mastering-voice channel count for the 3D mix. It also **pins the mastering voice to `kiMasteringSampleRate` (48 kHz)** — matching DataPacker's 48 kHz pack rate so source rate == mastering rate and XAudio2 skips its per-voice SRC (Windows shared-mode does any final device-rate conversion once at the mastering output). DirectXTK does not cache the ctor `wfx`, so the pinned format is stored (`mPinnedOutputFormat`, native channel count preserved) and re-applied on the device-reset `Reset` — passing `nullptr` there would revert to the device rate. Delegates to the static and streaming voice subsystems. `Update` refreshes the listener position before driving voice lifecycle so the priority pass sees current-frame listener and fade state.
  - **Stable engine / silent start contract**: construction always yields exactly one `AudioEngine` — when no endpoint produces one (no active device, a found device with a null id, or an empty/null endpoint collection), it is constructed against the OS default (`deviceId == nullptr`), which DirectXTK keeps as a silent-mode shell rather than throwing. **No enumeration path leaves `mpAudioEngine` null**; the only remaining null outcome is the ctor itself throwing for a non-device HRESULT (caught in the ctor catch, `Update`'s null guards stay). **The engine object is never recreated** after `StaticVoices`/`StreamingVoices` receive its raw pointer; a silent engine is recovered only via `Reset`. Init therefore splits **live-graph configuration** (`ConfigureLiveGraph` — pinned-format build, 48 kHz pin + device-default fallback, debug config, mastering diagnostics; entirely skipped in silent mode, where `GetOutputChannels() == 0` and `GetInterface()` is null) from the **one-time ownership attach** (`RegisterNotify` + both voice `Init`s, run exactly once even when silent). Ownership attach follows live configuration so the initial pin's synchronous `OnReset` is not observed.
  - **Pinned-format validity** (`AudioManagerFlags::kPinnedFormatValid`, in `mFlags`): true only once a live output graph produced `mPinnedOutputFormat` from real native channels; false for a silent start **and** when a startup pin left the graph silent (both the pinned and device-default Resets failed). Never dereference `GetInterface()`, cache mastering channels, or emit live-format diagnostics unless the final graph is present.
- **StaticVoices** - 3D spatial one-shots + frame-driven looping/persistent voices. Hard-capped pool of XAudio2 source voices keyed by `crc` (retired voices are recycled, not destroyed). The 3D one-shot path takes the one-shot mutex once and calls an unlocked emit helper (no re-entry). 3D sources asserted mono; the chunk-not-ready path requests a chunk load and bails for that frame.
- **StreamingVoices** - Music streaming. Reads incrementally from FileManager `LazyChunk` data — music is never fully resident, unlike static sound chunks. `StreamingVoice` owns one stream's transition predicate, triple-buffer fill/drain/submission, fade, and XAudio2 detachment state; `StreamingVoices` owns worker `Wait`/`Wake`, the mutex, current/previous containers, and crossfade orchestration. A per-slot atomic state machine publishes worker-filled slots to the main thread, whose `Update` is consumer-only; XAudio2's callback thread only bumps an atomic consumed-counter. Every public container mutation waits for the dedicated `common::PersistentWorker` (`kThreadStreamingVoiceFill`) first (`SetNextTrackCallback` is exempt because the worker never reads the callback), and only `Update` wakes it. Voice `Start()` is deferred to first buffer submission.

## Frame-Phase Invariants

- `AudioManager::Update` runs post-render on the main thread and owns all XAudio2 pumps and buffer submission.
- One-shot emit and static voice lifecycle both assert post-render phase and early-out during reconciliation replay — replay ticks must not mutate audio state in either direction.
- Static voice lifecycle reads post-render sound ids against the interpolation SOA.
- Audio is presentation-only: fades/crossfades advance on wall-clock real time (not sim time/timespeed), and pitch randomization uses a time-seeded random engine that never touches gameplay random streams or CRC state.

## Voice Lifetime

- Shared voice-teardown helper `DestroyXAudio2SourceVoice` lives in `AudioUtility.h` (client-only); it takes an explicit `AudioEngine*` — voice destructors do not reach through `gpAudioManager`. `StreamingVoice` holds `mpAudioEngine` (set in ctor) for this reason. `VolumeToPower` also lives in `AudioUtility.h`; both are included via `Engine.h`.
- Two teardown modes: XAudio2-already-destroyed (post-reset/device-loss — just null pointers) vs. we-still-own-the-voices (explicit `DestroyVoice` with >100ms teardown warning).
- `AudioManager` owns the sole suspend atomic; it gates music, both one-shot entry points, and `Update`. `Suspend` marks suspended, stops XAudio2 processing so `DestroyVoice` returns instantly, then clears static and streaming voices through the unified paired teardown; `Resume` re-enables normal on-demand recreation.
- Faded-out streaming voices are parked in a deferred-destruction list. `Update` drains it *after* the mutex releases — `DestroyVoice` must wait for `OnBufferEnd` without deadlocking the callback. `Clear` destroys *while holding* the mutex; safe only because `OnBufferEnd` is a bare atomic increment that never takes it (path-specific, not a class-wide invariant).

## Volume & 3D

- Combined volume squared for a perceptual curve; sfx and music use separate global sliders.
- Both `SetFrequencyRatio` sites (one-shot base pitch, 3D `DopplerFactor * fPitch`) route through `SnapFrequencyRatio` (`AudioUtility.h`): a computed ratio within `kfFrequencyRatioSnapEpsilon` (~5 cents) of 1.0 snaps to exactly 1.0, so slow-Doppler / non-randomized voices hit the XAudio2 SRC bypass instead of resampling for an inaudible pitch offset. Pitch randomization and Doppler computation are unchanged — only the final applied ratio is snapped.
- 3D mix layers X3DAudio (matrix / Doppler / LPF) with a manual piecewise distance fade as a hard override past the physical attenuation floor. The natural attenuation curve drives the priority pass; the audible-floor only clamps the final mix after prioritization, so it never makes a distant sound look loud to the prioritizer.
- Two listener points, decoupled by purpose. `mVecListenerPosition` (camera eye, full XYZ) drives the manual fade distance — altitude inflates 3D listener-to-emitter distance so high zoom pulls ground emitters into the fade band. `mX3dAudioListener.Position` (camera look-at on the world plane at `gBaseHeight`) drives X3DAudio pan/Doppler — pinning it to the world plane keeps the listener-to-ground-emitter vector XY-only, so pan azimuth reflects 'left-of-screen → left-ear' instead of being collapsed near-center by altitude. Listener velocity is zero; Doppler still applies from emitter motion.
- Fade band shape (start/end distance, X3DAudio curve scaler, audible-floor multiplier) is camera-height-lerped per the canonical "Camera-Height-Conditional Uniforms" pattern (see `Engine/Source/Graphics/Render/AGENTS.md`). Each quantity is a height-lerp wrapper quartet in `Engine/Source/Ui/SoundSettingsWrappersBase.cpp`, exposed in the **Sound > Tweaks** sub-tab; `UpdateListenerPosition` resolves them against eye height each frame. The audible floor is relative (multiplier × the sound's own volume), so a full-voice sound floors at a faint level past fade-end while a zero-volume voice stays silent regardless of distance — required because per-category volume wrappers default to 0.

## Voice Prioritization

- Static voice slots are scarce; allocation is closest/loudest-wins, not first-come. Per-frame priority pass scores entries by attenuated volume and reclaims XAudio2 voices from the lowest-scoring sounds when over budget.
- One-shots are hard-culled at submission when their attenuated volume falls below the cull threshold — they never enter the pool.
- Looping/persistent entries out of audible range release their XAudio2 voice but keep the bookkeeping entry (inactive state); they re-acquire a voice and fade in via the existing fade-volume on re-entry. Activation/deactivation use a hysteresis band around the cull threshold to prevent flicker at the boundary.
- Pre-emption (budget eviction and range-fall-out) does not instant-stop. The displaced voice enters a fade-out state and ramps down over the sound's configured fade-out time, starting from its current fade volume — a voice caught mid-fade-in never steps up. The ramp clamps at zero and retirement (per-CRC pool return, entry inactive) is deferred one frame so the applied silence reaches the XAudio2 voice before it stops — no mid-sample cut. A bounded fade-out pool sits above the main voice cap so the freed slot can be handed to the incoming sound immediately while the outgoing one finishes its tail. Overflow `DEBUG_BREAK`s and the deactivation retries next frame.
- Re-entry mid-fade is click-free: if a fading-out entry becomes audible again, the fade is cancelled in place and the regular fade-in ramp resumes from the current volume — no restart, no zero-volume blip. New-voice acquisition splits by origin: a pool-reused voice resumes mid-buffer at an arbitrary loop phase (pooled voices are never flushed), so it starts at fade volume 0 and rides the standard fade-in ramp, with the same-pass 3D mix scaled by the fade volume; a freshly created voice starts at full volume with the 3D mix applied before the first audio quantum — its buffer begins near zero amplitude, so no ramp is needed.
- Static-voice transition helpers keep fade-state/count synchronized and, for retained entries, pair inactive state with XAudio2 pointer attachment or retirement.
- Lifecycle is a fixed sequence of single-purpose passes per frame: invalidation marking, priority (handles both inactive and fading-out re-entry), deactivation marking, fade-out advance + retirement, fade-in ramp. Mark-only passes never mutate XAudio2 state directly — one exception: invalidation's already-silent shortcut returns the voice to the pool immediately (`ReturnVoiceToPool` → `Stop`), skipping the fade. The dedicated advance pass owns all other transitions.

## Device Reset

- Lost-device detection in `Update` branches on `AudioManagerFlags::kPinnedFormatValid`. **Valid pinned format** (a live graph completed startup configuration): call `AudioEngine::Reset` with the pinned 48 kHz format, guarded by try/catch at the DirectXTK trust boundary — DirectXTK's `Reset` returns false for a missing/busy device but *throws* on other failures (e.g. the pinned startup channel count exceeding a hot-swapped device's); on throw-or-false it falls back to a device-default `Reset(nullptr, nullptr)`. This path then re-caches the mastering channel count and clears voices via `FinishDeviceReset` **unconditionally**. **No valid pinned format** (silent start, or a startup pin that left the graph silent): a throttled probe (`kiSilentRecoveryRetryFrames`) resets to the device default to discover native channels, derives the pinned format, then pins — mirroring startup's `GetOutputSampleRate() != kiMasteringSampleRate` skip so a native-48 kHz device is not needlessly re-pinned — and restores the device-default graph if the pin fails. That recovery path calls `FinishDeviceReset` **only on successful recovery** (inside the `IsAudioDevicePresent` success gate). The silent-recovery pin runs against the just-restored live graph, so DirectXTK's `Reset` synchronously delivers a migration `OnCriticalError`; that notification is expected and suppressed (`AudioManagerFlags::kExpectedResetInProgress`, set across the pin/fallback window) so it is not logged as a false critical error. The throttle plus a log-once warning keep a permanently-deviceless machine from warning + full-resetting every frame (the stable silent engine makes `!IsAudioDevicePresent()` true every frame). On a successful recovery `Update` falls through to `CheckTrackTransition`, whose existing null-current-stream path asks the next-track callback for exactly one track.
- DirectXTK's XAudio callback only signals a critical-error event; `AudioEngine::Update` and `Reset` deliver audio notifications synchronously on the caller/main thread. `OnReset` sets one paired-clear request consumed at the top of the next `AudioManager::Update`, keeping fill-worker `Wait`/`Wake` main-thread-only. The reset path consumes its own synchronous request before its explicit paired clear so a newly restarted track survives the next frame; `OnCriticalError` performs the paired clear immediately. Once the device is available after any clear, a null current stream asks the next-track callback for the next playlist track.
