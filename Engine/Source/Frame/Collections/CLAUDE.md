# Collections - SOA Collection Framework and Engine-Level Collections

## Overview

Template-based Structure-of-Arrays (SOA) collection system providing memory management, serialization, GPU rendering, and deterministic CRC validation. Engine collections cover lights, effects, audio, physics, and wind, split between always-compiled (server-relevant) and client-only via `#ifdef BT_CLIENT`. Also defines `global_id_t` (stable cross-session entity identity) with `GlobalIdHash` and a `std::formatter<global_id_t>` for direct use in `LOG()`.

## Key Systems

- **Collection\<T\>** (`Collection.h`) — template base managing count, capacity, contiguous SOA buffers. `CollectionFlags::kIdToIndex` enables stable external references via strong-typed `id_t<T>` (tag `T` prevents mixing IDs across collections; 0 == invalid). Provides `TypeRegistry`, `ControllerTypeRegistry` (keyframe animation), deterministic serialization/CRC, and metadata-level `LogDifferences()` (count/capacity/map size). Per-element desync diagnosis is the same `LogDifferences()` family — per-field `common::LogDifference<...>` in each collection's override
- **CollectionMemory** (`CollectionMemory.h`) — SOA memory templates: sizing, 64-byte-aligned allocation, capacity growth, element add/remove/swap for basic and indexable paired Interpolate/PostRender collections. The shared `AllocateCore` (behind `Allocate`/`AllocateAndCopyIds`) copies previous-frame metadata and reallocates on capacity change, returning false when previous-frame data was null — a signal available to callers, with no current consumer
- **Server Collections** (always compiled) — [Explosions](Explosions/CLAUDE.md), [Pushers](Pushers/CLAUDE.md)
- **Client Collections** (`#ifdef BT_CLIENT`) — [AreaLights](AreaLights/CLAUDE.md), [Billboards](Billboards/CLAUDE.md), [PointLights](PointLights/CLAUDE.md), [Puffs](Puffs/CLAUDE.md), [SmokeTrails](SmokeTrails/CLAUDE.md), [HexShields](HexShields/CLAUDE.md), [WindTrails](WindTrails/CLAUDE.md), [WindRadials](WindRadials/CLAUDE.md), [Sounds](Sounds/CLAUDE.md)

## Hub-Owned Conventions (leaves do not re-state)

- **SOA layout invariant**: single contiguous `AlignedUniquePtr<std::byte>` buffer; every member pointer individually 64-byte aligned within it. Capacity growth is `2 * capacity + 1` — fixed because `iCapacity` participates in the collection CRC, so capacity must evolve deterministically. `AllocateAndAssign` reuses the existing buffer when current capacity already suffices
- **Member tuple protocol**: collections expose `Members()` (full SOA set) and optionally `SharedMembers()` / `ClientMembers()` (the cross-build-shared subset vs. `#ifdef BT_CLIENT` extras). Tuple entries are either a single `T*` or a C-array-of-pointers `T* pp[N]`; every helper (sizing, alignment, CRC, serialize, swap) handles both forms. When a collection defines `SharedMembers()`, CRC and server-stream read operate on that subset only — the shared read allocates and zero-fills the full `Members()` buffer (so client-only pointers stay valid) but deserializes just `SharedMembers()`, keeping client-only fields out of determinism. The server build `static_assert`s that a shared collection's `Members()` is the identical tuple to its `SharedMembers()` — the server broadcasts by walking `Members()` while clients read `SharedMembers()`, so wire/CRC parity depends on that equality. **Never add a `#if defined(BT_CLIENT)` member to a `Members()`-only leaf** — it would be CRC'd and wire-serialized into the determinism path with no compile error (the parity `static_assert` fires only on collections that define `SharedMembers()`). Give the leaf a `SharedMembers()` first (with the client field in `ClientMembers()`); a leaf with no client fields yet can pre-empt the trap by defining `SharedMembers()` as its full set and `Members(){ return SharedMembers(); }` (e.g. `SpaceshipsPostRender`)
- **Paired Interpolate/PostRender invariant**: spawn/remove helpers keep `iCount` in lockstep across both; indexable PostRender structs must expose `puiIds` for swap-and-pop map fixup. Never mutate `iCount` directly — go through the Add/Remove helpers
- **Dual-dt Update contract**: the same `FrameInterpolate::Update` fan-out serves sim phase 1 at fixed dt inside `RunFrameTick` (`kfDeltaTime`) and client render interpolation at variable dt (`GameBase::Render` — can be 0.0 while snapshots buffer); inside `Update` the regimes are indistinguishable; only the resulting frames are tagged via `frameFlags` (render-interpolated frames carry `kInterpolate`, simulated frames end stamped `kPostRender`, replay re-sims add `kRecalculated`; all client-only — the server knows just the fixed-dt regime). Every interpolate-phase `Update` must be safe under both: no once-per-tick assumptions, correct at any dt including zero
- **Swap-and-pop removal**: `SwapElement` / `DestroyElement` are O(1) unordered. `DestroyElement` decrements the caller's loop index (`--i`) — callers must use `int64_t i` and re-check bounds after the call
- **Sync pattern (owner-driven lifetime)**: external parent calls `Add()` -> `Sync()` every frame -> `Remove()`. `Add()` must zero-initialize all Interpolate fields (stale pre-first-Sync memory causes CRC desync). Owner-driven collections commonly leave every PostRender phase hook (`Update`, `PreCollision`, `PostCollision`, `AreaDamage`, `Transfer`, `Destroy`, `Spawn`) and often `Register()` as empty stubs — parent handles transfer, lifetime, and type registration. Leaves do not re-document empty stubs; they document only the phase methods with actual logic
- **Uniform phase-hook signatures (`[[maybe_unused]]`)**: every collection phase method (`Update`/`PreCollision`/`PostCollision`/`AreaDamage`/`Transfer`/`Destroy`/`Spawn`/…) shares the family's fixed signature so the `ForEach*` fold helpers can call it generically. Mark all parameters `[[maybe_unused]]` — stubs and partial implementations won't use them all — and keep the attribute even when a body does use the parameter; never strip it to "tidy up". See [Frame/CLAUDE.md](../CLAUDE.md).
- **Controller pattern (fire-and-forget)**: `AddControlled()` with keyframe animation auto-destroying on expiry. Shared `InterpolateKeyframes<>()` / `DestroyExpiredControlled()` in `Collection.h` work with any controller type exposing the standard keyframe layout. Optional per-keyframe `Wrapper*` arrays enable normalized multiplier keyframes scaled by a runtime base magnitude
- **Type registration side effects**: on the client, registering a type whose config carries a nonzero texture `crc`/`particleCrc` automatically schedules the texture chunk load (FileManager) and lighting-texture pre-blur registration (TextureManager) via free functions forward-declared in `Collection.h` — registering a type triggers asset I/O. Registries are register-once (asserted)
- **Determinism rule**: visual-only spawns must use `id_t::GenerateVisual` / `uuid_t::GenerateVisual` (and `AddVisualIndexableElement`) so visual creation does not perturb the main UUID counter. Transfer/reconnect re-adds use `AddIndexableElementWithId` so the server-issued ID survives. Random calls must run unconditionally on both builds even when the consuming spawn is client-only
- **Heap policy**: SOA buffer / `idToIndexMap` / render-state-map mutations wrap in `ScopedSuppressAllocationTracking` because they persist across frames (workbuffer unsuitable). Mandatory, not advisory — see inline `// Heap:` notes
- **Render-only state pattern**: when render needs previous-frame data outside dual-buffered frame state, use file-scope statics keyed by `id_t<T>`. `EraseStaleRenderState<>()` prunes entries whose IDs no longer appear in any active frame's `idToIndexMap`
- **GPU pipeline**: each renderable collection owns its pipeline(s) and buffers. Three-phase render (BeginRender/Render/EndRender) pre-sizes GPU buffers across all active grid coords via `AccumulateRenderCapacity()`. File-scope `siRendered` / `siTotalCount` cursors accumulate across `Render()` calls and publish through CPU profile counters; `EndRender` writes the indirect draw count
- **Extern template**: every collection header declares `extern template struct Collection<T>` to cut compile times
- **File splitting**: large collections split across `.cpp` files (core, update, render) sharing a single `.h`
- **Adding members**: use the `add-collection-member` skill's checklist
