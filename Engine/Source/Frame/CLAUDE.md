# /Engine/Source/Frame/

Core game state management with deterministic dual-buffered frame system and fixed timestep updates.

## Overview

Manages frame state through a two-phase update system (Interpolate/PostRender) that separates rendering preparation from game logic. Frame state uses composition: `game::Frame` aggregates `FrameInterpolate` and `FramePostRender`, with game-specific classes extending the engine base classes. Each frame provides equality comparison, CRC generation, and serialization for deterministic replay.

## Key Systems

- **GridCoord** (`GridCoord.h`) - 2D coordinate for keying Frames in the sparse grid, with key packing, serialization support, neighbor offset constants, and `std::hash` specialization
- **TimeStep** - Fixed timestep accumulator converting variable render time into discrete physics steps. Provides time scaling for slow-motion/fast-forward, interpolation alpha for smooth rendering between ticks, and death spiral prevention that auto-reduces time multiplier when excessive updates are detected
- **FrameUtils** - Template utilities enabling automatic iteration over all collections via compile-time type lists and fold expressions. Provides `ForEach*` helpers that invoke static methods across all collection types, plus `AllocateAndCopyCollections` and `CompareCollections` for tuple-based bulk operations
- **FrameInterpolateBase** - Rendering-phase state containing frame timing and all engine-level Interpolate collections. Declares explicit move constructor/assignment (user-declared destructor suppresses implicit move generation). GameBase owns the authoritative frame counter and simulation time, propagating them into every active frame. Uses C++23 deduced `this` on `Collections()` to enable automatic iteration for CRC, serialization, and comparison. Orchestrates the three-phase render pipeline (BeginRender/Render/EndRender, client-only). SmokeTrails and WindTrails are excluded from the standard render type list because they require a per-frame ID parameter. `kCollectionCount` and `static_assert`s enforce that `Collections()` tuple stays synchronized with the actual collection members. Visual-only collections (AreaLights, Billboards, HexShields, PointLights, Puffs, Sounds, SmokeTrails, WindRadials, WindTrails) are conditionally included via `#ifdef BT_CLIENT`, with `kCollectionCount` adjusting accordingly (11 client, 2 server: Explosions and Pushers). `ServerRead()` deserializes server-format streams by reading scalar fields and using `ServerCollectionRead()` on `ServerCollections()` only, enabling the client to reconstruct server state with zero-initialized client-only fields
- **FramePostRenderBase** - Logic-phase state containing deterministic random engine, per-Frame UUID generator, world-space area bounds, and all engine-level PostRender collections. Declares explicit move constructor/assignment (user-declared destructor suppresses implicit move generation). UUID generation encodes Frame ID to ensure uniqueness across multiple Frames without atomics. Orchestrates the seven PostRender sub-phases via ForEach helpers. `kCollectionCount` and `static_assert`s mirror FrameInterpolateBase to enforce paired collection consistency. Client-only UUID counters (`uiNextSoundUuid`, `uiNextVisualUuid`) generate IDs for Sounds and visual objects (AreaLights, Billboards, HexShields, PointLights, SmokeTrails, WindTrails) independently so client-only object creation does not perturb the main UUID sequence used for server-relevant entities. `ServerRead()` deserializes server-format streams, skipping client-only UUID counters and using `ServerCollectionRead()` on `ServerCollections()` only
- **IslandTerrain** (`IslandTerrain.h/cpp`) - Stateless CPU terrain collision queries shared by both client and server. Provides `GlobalElevation()` and `GlobalNormal()` for world-space terrain sampling across infinite grid cells, computing grid cell and UV from world position with parity-based flipping for seamless tiling. Loads heightmap data from pack files via FileManager lazy loading. Also provides `TerrainCollision()` free function for ray-marching terrain intersection. Global `gpIslandTerrain` pointer. Created before Graphics (client) or as the sole terrain system (server)
- **Collision** - Layer-based collision detection with fixed-size grid spatial partitioning. Collections register layers in PreCollision and query results in PostCollision. Supports both discrete sphere overlap and swept sphere tests for fast-moving objects (enabled per-layer via `bSweptTest`). Swept tests use velocity-based AABB expansion for broad-phase zone insertion, then quadratic swept sphere intersection for narrow-phase, returning earliest contact time within the frame, with fallback to discrete overlap for already-overlapping cases. Uses pre-allocation with count-based reset to avoid per-frame heap allocations, with growth beyond pre-allocated capacity logging the overflowed container and relevant constant before triggering `DEBUG_BREAK()`. Zone structures are built per colliding layer pair. Collision masks must be bi-directional (enforced via assert), and same-layer collision is not supported. Also provides an area damage system for explosions with linear falloff queries
- **Alignments** - Sparse relationship map for collision filtering between aligned objects. Uses a sorted flat vector with binary search for O(log n) lookup. Alignment state is owned by the game layer and passed to collision. Invalid alignment (0) collides with everything
- **Render** - Frame rendering orchestration populating GPU uniform buffers. Splits into global uniforms (sun, shadows, terrain, water, day/night cycle) and per-frame uniforms (camera, lighting, PBR). Provides smoothly interpolated elapsed time that respects time scaling and pausing. Manages smoke and wind compute simulations that run every render frame with ping-pong texture patterns and shared visible-area coordinate space. Implements the three-phase render pipeline across all active frames, with the camera frame rendering first for index-0 stability. Includes batch object rendering with visibility culling and indirect draw buffer management

## Frame Update Flow

**Interpolate Phase**: Calls AllocateAndCopy() on all collections to prepare memory, then Update() to smooth positions for rendering. Frame counter and simulation time are set by GameBase before this phase runs.

**PostRender Phase** (seven sub-phases):
1. **Update** - Input-driven logic, random state propagation
2. **PreCollision** - Collections register collision layers
3. **PostCollision** - Collections query collision results, apply damage, flag out-of-bounds entities with kTransfer
4. **AreaDamage** - Collections query explosion damage with falloff
5. **Transfer** - Collections generate TransferRequests for kTransfer-flagged entities and remove them
6. **Destroy** - Clean up flagged objects (kExploding/kDestroy)
7. **Spawn** - Create new objects from spawn requests (operates on Frame only, no FrameInput parameter)

## Architecture Notes

- Collection serialization uses `Collections()` with `std::apply` and fold expressions to automatically iterate all collections without manual per-collection calls
- **Dual CRC system**: `Crc()` computes the full checksum including all collections (client build). `ServerCrc()` computes a cross-build-compatible checksum excluding client-only data (visual collections, `uiNextSoundUuid`, `uiNextVisualUuid`) via `ServerCollections()`, enabling server builds to validate determinism against client builds. Both FrameInterpolateBase and FramePostRenderBase provide `ServerCollections()` and `ServerCrc()` methods returning only Explosions and Pushers, and game-level Frame structs propagate this with their own `ServerCrc()` static methods. **Server comparison**: `ServerCompare()` methods mirror the `ServerCrc()` hierarchy but perform explicit per-field `BreakOnNotEqual` comparison instead of CRC computation. Each collection implements its own `ServerCompare()` that compares only shared fields (using `SharedMembers()` for collections with client-only fields, or delegating to `operator==` for server-only collections). FrameInterpolateBase and FramePostRenderBase `ServerCompare()` methods compare scalar fields and dispatch to each collection's `ServerCompare()`, and game-level Frame structs propagate through the hierarchy. This enables precise field-level desync diagnosis when CRC mismatches are detected. **Server deserialization**: `ServerRead()` methods at each level (FrameInterpolateBase, FramePostRenderBase, and game-level Frame structs) deserialize server-format streams that contain only server-relevant fields, using `ServerCollectionRead()` to allocate full client buffers (zero-initialized) while reading only the server-written subset
- FrameFlags bitmask tracks the current update phase and prevents duplicate side effects during interpolation. The kRecalculated flag guards non-deterministic side effects (audio playback, GPU particle spawning) that should not repeat when frames are recalculated
- IsVisible() provides axis-aligned visibility checks for AI targeting decisions
- **Load/Save local variable paradigm**: Frame update methods load previous frame state into locals, modify, then save to current frame. This pattern is only appropriate for trivially copyable types (scalars, XMVECTOR, small POD structs). Heap containers should use direct assignment or dedicated `CopyFrom()` methods to allow buffer reuse and avoid unnecessary allocations

## Constraints

- **No transient metadata in Frame structs**: Frame structs must only contain their actual logical state. Do not add derived or convenience fields (e.g., GridCoord) -- such data is external to the frame and belongs in the lookup infrastructure (maps, render state, etc.).
