# Frame - Core Game State and Fixed-Timestep Simulation

## Overview

Manages per-frame game state through a dual-phase update system (Interpolate for rendering, PostRender for logic) over a sparse grid of simulation cells. `game::Frame` aggregates engine base classes (`FrameInterpolateBase`, `FramePostRenderBase`) with game-specific extensions. Collections get automatic CRC, serialization, and comparison via compile-time type lists.

See also: [Frame Update Pipeline](../../../Documents/Architecture/FrameUpdatePipeline.md) — update this diagram if phase ordering changes.

## Key Classes

- **FrameInterpolateBase / FramePostRenderBase** - Split base classes for render-phase vs. logic-phase state. PostRender orchestrates sub-phases (Update, PreCollision, PostCollision, AreaDamage, Transfer, Destroy, Spawn) and owns determinism infrastructure (CRC chain, deterministic random, UUID streams).
- **FrameStaticData** - Per-coord data stored in `CoordFrames`: area bounds, the cell's island placement list (CRC + world position + rotation each), and two `mutable` derived caches (`NavData`, per-cell elevation grid). The serialized placement list is the source of truth; the two caches are rebuilt deterministically on the per-coord frame-tick thread and excluded from the save format. Server builds NavData from placements (rebasing each template's `NavContour` into world space); clients receive it via network serialization.
- **FrameUtils** - Template helpers using `std::apply` + fold expressions to iterate all collections for CRC, serialization, and copy. Also exposes the shared movement model (drag/acceleration/max-speed with optional velocity-to-direction blending).
- **TimeStep** - Fixed-timestep accumulator with time scaling and backlog clamp; death-spiral auto-reduction compiles only under `kbDebugInput` (debug builds). Also drives the client sim-ceiling clamp, not just stalls.
- **Collision** - Layer-based spatial partitioning (fixed zone grid) with discrete and swept sphere tests; swept falls through to discrete on already-overlapping. Per-pair masks must be bi-directional (asserted); same-layer collision unsupported. Results land in flat `thread_local` storage via prefix-sum spans.
- **AreaDamage** - Thread-local accumulator for explosion/AoE sources with linear falloff and category-bitmask filter; populated in PostCollision, queried in AreaDamage phase.
- **Alignments** - Sparse collision filtering via sorted flat vector with binary search; key is lower-id-first so `(A,B) == (B,A)`. `CanCollide` is true only when the pair exists and is flagged enemies — an absent pair means no collision.
- **IslandChainPlacement** - Deterministic per-cell archipelago generator, seeded only by the grid coord so client and server produce identical layouts. Builds a chain by contact growth: a Huge anchor at index 0 in the SW third, then a fixed sequence of Large + Medium links each placed just-touching the chain tip along a hard-turning curve (truncated where the next link would leave the cell), then Small islets ringing each big island (touching a big island only, never another small) plus a few trailing off the curve's end. Every island packs by its rotated valid-area convex hull so no two hulls overlap (bounding rectangles may overlap, hidden underwater). Role selection draws from `IslandTerrain`'s size buckets.
- **IslandTerrain** - CPU terrain queries (elevation, normals) shared by client and server, plus client-only GPU residency for the renderer. Holds one template per kIsland manifest chunk, keyed by CRC, and classifies them into Huge/Large/Medium/Small size buckets by footprint area (sorted-CRC order within each, so deterministic across builds; empty buckets fall back through related buckets). Templates are anisotropic (`mfQuadFootprintX`/`mfQuadFootprintY`, derived from asset meters via `kfMetersToUnits`, currently 1:1). Heightmaps store absolute elevation in meters (R32_SFLOAT): sample 0 is the beach/sea level, negative underwater, positive land — DataPacker has already scaled and offset the values, so the engine samples directly (see [DataPacker/Source/CLAUDE.md](../../../DataPacker/Source/CLAUDE.md) for the per-island beach offset, shoreline mesh densification, and crop/align rules). Elevation/normal queries split by caller to honor the Frame Purity Constraint:
	- **Sim hot path** (`FrameElevation`/`FrameNormal`) reads the per-cell elevation grid handed in via the cell's `FrameStaticData` — never touches `mCoordFrames`, never crosses cells (out-of-cell returns the sea floor). The grid is built once at the top of `RunFrameTick` by max-blending each placement's heightmap; client and server build bit-identical grids from the deterministic placements, and the grid is neither serialized nor in the CRC.
	- **Render path** (`GlobalElevation`/`GlobalNormal`) walks `mCoordFrames` placements directly (same max-blend, finite-difference normals) and must never run from frame-tick code.
- The client side additionally owns lazy CRC-to-bindless-slot assignment, GPU mesh buffers, the elevation GPU image, and LRU eviction/restoration of terrain G-buffer textures. Mesh buffers and the in-memory heightmap stay permanently resident (mesh created once at boot to satisfy the record-once CB invariant; `Main` runs `WaitForElevationMaps` before `Graphics` is constructed). The texture/elevation residency, slot-0 placeholder fallback, and eviction-symmetry invariants live in [Graphics/Managers/CLAUDE.md](../Graphics/Managers/CLAUDE.md).
- **NavBuild / NavQuery** - Visibility-graph pathfinding over per-cell NavData. Direct LOS fast path with A* fallback. NavData splits into serialized vertices/polygons/visibility edges and a derived broad-phase acceleration layer (polygon AABBs, obstacle-edge grid, per-vertex adjacency) that is rebuilt deterministically from the serialized data on both sides — server after build, client/load after read — so it is never serialized and never touches the version. Bump `kiNavDataVersion` only when the serialized NavData layout changes (feeds into `Frame::kiVersion` for save compatibility).

## Architecture Notes

- **CRC system**: Single shared CRC excludes both client-only and server-only fields, cached after update. Drives cross-build determinism validation and reconciliation fast-path. `ServerCollections()` is the cross-build-shared subset walked by CRC, `ServerRead`, and `LogDifferences`; client-only collections stay out of determinism.
- **Collection registration**: `Collections()` tuple size is `static_assert`-locked to each base's `kCollectionCount`, and the two bases must agree. When adding a Collection pair, update both `kCollectionCount` constants and (if shared) `ServerCollections()` alongside the `Collections()` tuple.
- **Client/server split**: Visual-only collections gated by `#ifdef BT_CLIENT`.
- **thread_local lazy-init**: `Collision` and `AreaDamage` thread_local vectors must start empty — constructors run during `mi_process_init` before the allocator is ready. First-use resize and overflow growth wrap realloc in `ScopedSuppressAllocationTracking` and (on overflow) `DEBUG_BREAK` naming the preallocate constant to raise.
- **No transient metadata in Frame structs** — only logical state belongs here; derived data goes in lookup infrastructure.
