# Graphics - Vulkan Rendering System

## Overview

Multi-pass deferred Vulkan renderer with lighting, shadows, GPU particles, and post-processing. Entirely client-only. `gpGraphics` owns all managers and coordinates a three-submission render loop (Global, Main, ImGui).

## Architecture Notes

- Record-once command buffers resubmitted every frame; re-recorded only on resize or settings change
- **CB re-record is banned outside the swapchain / settings / device-loss recreate paths.** All per-frame state variation must flow through host-visible buffers: SSBOs (the per-framebuffer island storage array), per-frame uniforms (`mGlobalLayoutUniformBuffers`), or indirect-draw commands (`Pipeline::WriteIndirectBuffer`). The terrain pipeline is the cautionary example: a since-removed earlier version bound per-island mesh buffers and instance counts at C++ record time, then relied on capacity-grow re-records to refresh them. Within its default capacity the re-record never fired and new islands silently failed to draw despite their textures, mesh, and slot all being resident. The fix records one `vkCmdDrawIndexedIndirect` per template (template count fixed at boot from `gpIslandTerrain->mIslandCrcsSorted`); per-template `instanceCount` is rewritten each frame into a host-visible indirect buffer. For per-instance mesh selection that doesn't fit a single bound vertex buffer, mirror that pattern: one indirect draw per template, mesh bound at record time.
- Per-framebuffer descriptor sets prevent GPU conflicts across frames in flight
- All GPU memory allocated through VMA
- Lazy texture loading: generic textures use a white placeholder at startup; islands use a permanent neutral programmatic placeholder at slot 0 (format-matched, never adopted by a real island), with background disk load via transfer queue and deferred descriptor update. Frame 0 renders no islands — visible terrain appears only as subscriptions arrive and mint slots
- Camera snaps render visible-area to the water quad grid — never render off-grid. Terrain uses per-island Gaea2-Mesher meshes and samples per-island color / normal / AO bindless arrays directly in the fragment shader; the only remaining composite RTT is the elevation prepass (R16_SFLOAT, `shaders::keElevationFormat`), sized by the snap-grid (driven by `BufferManager::mWaterMeshLods`) and consumed by terrain, water, and shadow passes
- Terrain collision queries live in `/Frame/IslandTerrain` (shared); `Islands` here is client-only GPU rendering
- Frame boundary sits between Main-submit and the next Acquire, not at loop top
- `RenderGlobal` post-fence-wait is the descriptor-patch safety window: island LRU eviction runs immediately before `TextureManager::ProcessPendingTextures` and restoration runs immediately after, so descriptor rewrites happen while no frame-in-flight references the slots. The current-framebuffer fence wait alone is insufficient under triple buffering, so on churn frames only (gated on a cheap pre-scan: any pending eviction, restoration, or texture adoption) `RenderGlobal` first drains all framebuffer fences (a graphics-queue-only wait, not `vkDeviceWaitIdle`); steady-state frames pay no stall. The adoption term covers the `ProcessPendingTextures` descriptor writes (per-slot island, array flush, lighting-blur); restoration stays a distinct predicate because its template-owned elevation array write has no `mTextureMap` entry. Elevation slots are patched inside `IslandTerrain::RestorationSweep` (not `ProcessPendingTextures`) via `TextureDescriptors::UpdateArrayBindingsForKey`, because elevation is uploaded directly from the in-memory heightmap and bypasses the chunk-adoption flow (the template owns the Texture; there is no `mTextureMap` entry to drive the CRC-keyed update)
- `muiFrameCounter` increments unconditionally each frame (not gated by `VK_EXT_memory_budget` polling); the island LRU grace clock depends on monotonic advance on every device
- Guard scope is mixed: `Graphics.cpp`, `GraphicsUtils.cpp`, `Islands.*`, and `CameraBase.*` are `#if defined(BT_CLIENT)`-wrapped; `AnimationData.*`, `OneShotCommandBuffer.*`, `Screenshot.*`, and the `Graphics.h`/`GraphicsUtils.h` headers are unwrapped — client-only purely via client-vcxproj membership and `Engine.h`'s `BT_CLIENT` span. Never add the unwrapped files to the server vcxproj; game sim code touching `gAnimationDataMap` must carry its own `BT_CLIENT` guard. All `Managers/` and `Objects/` subdirectory cpps are whole-file `#if defined(BT_CLIENT)`-wrapped and client-vcxproj-only — keep new cpps in those directories wrapped so an accidental server-vcxproj add fails at the preprocessor, not at link. The `Managers/` and `Objects/` *headers*, by contrast, are unwrapped — they are client-only purely because every one is included inside `Engine.h`'s single `BT_CLIENT` span (`Engine.h:21`, Objects headers at `:29-34`) and the cpps that consume them live only in the client vcxproj; a header has no preprocessor guard of its own

## CameraBase

Game `Camera` derives from `CameraBase` (root CLAUDE.md's base-class rule applies). Owns the view/perspective matrices, the snapped render-visible-area rectangle, `ScreenToWorld` ray-plane unproject, and the visible-area LOD.

- **Snap-grid stability is the central invariant.** The visible-area edges are `RoundDown`-snapped to a quad grid so terrain/water/shadow RTTs never render off-grid. `floor(area / quadSize)` amplifies any `quadSize` jitter by `~area/quadSize`, so `quadSize` must be bit-identical across consecutive frames or high-contrast edges shimmer on continuous Z motion. Two latches enforce this: an integer-eye-distance **zoom bucket** (with hysteresis) latches `f2VisibleAreaQuadSize`, and a **LOD bucket** (`floor(log4(eyeDist / minEyeHeight))`, 5% hysteresis at the `minEyeHeight * 4^L` boundaries) selects mesh density + snap coarseness in lockstep. Quad counts per LOD come from `BufferManager::mWaterMeshLods` (water still uses the concat quad-grid; terrain uses per-island Gaea2 meshes but the composite snap-grid persists).
- **Shadow texels are world-sized (adaptive but rate-limited), not LOD-stable.** The shadow texture is allocated (RenderTargetTextures) at `game::Camera::kfShadowHeadroomMultiplier` (1.5x) the wanted on-screen pixel size as headroom; the texel world size scales by the camera's rate-limited shadow-texel height, so it is fixed at a settled eye height — snap-stable under XY pan, no resample, no pop, no shimmer when parked or panning. That height ramps toward live eye height at a tunable meters-per-second cap (no clamp — it tracks at all heights), so the texel grid only rescales (an imperceptibly slow crawl) while tracking a zoom and re-snaps once the height settles. A temporal-accumulation pass (history reprojected by world position, EMA-blended) removes the residual edge flicker that crawl still leaves. `f4ShadowArea` is the camera-centered footprint snapped to that texel grid. The ray-marched sub-window is constant on-screen (= textureWidth / headroom) at every settled height: as the camera zooms out the texels coarsen (world detail drops, on-screen density holds) rather than cropping coverage. Only a fast zoom-out that outruns the ramp transiently overflows the texture, where the CLAMP_TO_BORDER edge reads as no-shadow until the ramp settles. The lighting deposit/spread/combine path mirrors this exact mechanism: `f4LightingArea` is a camera-centered world-sized-texel rectangle over headroom-multiplied textures, scaled by an independent rate-limited lighting-texel height, with its own temporal-accumulation pass; spread/combine early-out outside the on-screen window.

## Destroy / Refresh Pipeline

Settings-change detector escalates a destroy tier (`DestroyType`) monotonically via `std::max`, with fine-grained resource subsets in a flags bitmask. `Destroy()` drains all in-flight submissions and `vkDeviceWaitIdle`s before touching resources. Texture recreation is selective (driven by `DestroyFlags`); pipeline-tier events drop and reconstruct the entire `PipelineManager` so descriptor sets are always freshly written against current texture handles. Partial destroy preserves texture/buffer managers and stashes the old swapchain for seamless recreation. Lighting-blur tweaks bypass the destroy pipeline entirely — textures are re-blurred in place.

## GraphicsUtils / Helpers

- `CheckVkFailed` auto-escalates swapchain/surface-loss results into destroy tiers; `DEVICE_LOST` throws `DeviceLostException` (caught by main loop to recreate Graphics in place)
- `CHECK_VK` macro forwards to `CheckVk`/`CheckVkFailed`, which breaks once (after logging) only on the fatal unexpected-result path; recoverable results (swapchain/surface-loss escalate to a destroy tier, device-lost throws `DeviceLostException`) do not break
- Debug-name strings interned because Vulkan retains the `c_str()`; insertion wrapped in `ScopedSuppressAllocationTracking`
- Shared collection-render helpers live here: visible-area point test, base-height projection (camera-relative terrain elevation), axis-aligned quad layout build (used by non-island quad consumers; islands write their own SSBO layout in Islands.cpp), and physical-device format-feature queries
- `OneShotCommandBuffer` — RAII wrapper for init/transfer work on the graphics queue; instances share one pool/fence and must not overlap (assert-enforced)

## AnimationData

- Zero-copy: node/channel/keyframe/material pointers index directly into eagerly-loaded pack memory
- Map populated once in the `Graphics` ctor from FileManager's eager scene chunks; idempotent early-out so device-loss recreation skips it — the map and the FileManager-owned pack memory it points into outlive Graphics
- Matrix convention: DirectXMath row-major storage reinterpreted by GLSL as column-major is already the transpose — never `XMMatrixTranspose` before upload
- Topological node order invariant (`iParentIndex < i`) enables single-pass world-matrix build
- CUBICSPLINE path uses glTF-spec Hermite tangents scaled by delta; STEP/LINEAR uses a compact keyframe
- Temp TRS/world-matrix arrays come from `gpThreadLocal->mWorkbuffer`, never heap

## Islands / Screenshot / Resolution Helpers

- `Islands` bridges island state into a per-framebuffer host-visible storage buffer array (one instance per framebuffer index, sized for the boot-fixed template count × `kiMaxPlacementsPerTemplate`); the indirect-draw buffer is per-framebuffer the same way. Each frame writes only the instance for the framebuffer it records, so triple-buffered in-flight frames never read a buffer the CPU is rewriting. Inactive slots are zero-width quads (GPU-culled). No capacity-grow path — template set is frozen at boot, see the CB re-record ban above
- Screenshot save waits the target framebuffer's fence, copies present image to host memory, then `std::async`-saves JPG with its own `ThreadLocal` (runs off the engine worker pool); a static future serializes overlapping saves
- Render-target size aligns to shadow-block boundaries expanded past framebuffer extent; smoke-sim resolution scales relative to a 3840-px reference width. Water-mesh detail (`WaterFullDetail`) uses the same block snap but anchors to a fixed 3840x2160 reference instead of the live extent — Gerstner wave frequencies are fixed, so the water vertex grid must be resolution-independent. The shadow texture (+ blur + 1.5x-wide elevation texture) is allocated 1.5x the wanted on-screen pixel size via `game::Camera::kfShadowHeadroomMultiplier` as headroom — the texel world size that actually maps onto it scales with the camera's rate-limited shadow-texel height (fixed at a settled height; see CameraBase), so this allocation never changes; the width is capped at `(maxImageDimension2D/3)*2` so the 1.5x-wide elevation variant still fits the device limit
