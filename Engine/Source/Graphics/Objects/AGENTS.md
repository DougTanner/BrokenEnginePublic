# Graphics Objects - RAII Vulkan Resource Wrappers

## Overview

Low-level Vulkan resource wrappers with automatic lifecycle management, move semantics, and VMA-based GPU memory allocation. Each object type is owned by its corresponding manager in `Managers/`. `Texture`, `Buffer`, `Pipeline` / `ModelPipeline`, `Shader` (thin SPIR-V module + reflection-data holder; asserts the magic number on create), and `CommandBuffers` (per-framebuffer pool + the Global / Main / ImGui command buffers, finished-semaphores, and fence that drive the three-submission render loop). `PipelineCreator` and `PipelineDescriptorWriter` are stateless helper structs that `Pipeline::Create` delegates layout/pipeline construction and descriptor writing to.

**Destroy discipline:** `Buffer::Destroy` / `Texture::Destroy` / `Pipeline::Destroy` are immediate (no internal fence wait); the caller owns the fence discipline. Never `Destroy` a possibly-in-flight resource outside a drained window — the three sanctioned strategies are the full-drain `vkDeviceWaitIdle` destroy path, one-frame buffer parking in `BufferManager::GrowMeshDataBuffer`, and the `RenderGlobal` post-fence-wait descriptor-patch safety window.

## Descriptor Model

- Pipeline descriptor arrays terminate at the first empty entry; bindings sequential unless a `DescriptorInfo` sets an explicit binding number (used when two pipelines share a resource at a fixed slot). Any deferred-registration or `Update*` call site that takes a binding parameter must pass the resolved Vulkan binding (`iExplicitBinding` when >= 0, else the sequential index) — never the loop counter. Deferred-registration APIs assert at register time that the binding number exists in the pipeline's shader-reflected layout; the same invariant covers the bindless-array consumer map. Catch the loop-counter / explicit-binding mismatch on frame 0 instead of on first sampler-recreate. Bindings 15/16 reserved for mesh-data / joint-matrix storage buffers (joint matrices split into their own dynamically-sized buffer so mesh data stays fixed-size).
- Model descriptor auto-appends follow-on descriptors (lighting, shadow blur, smoke, mesh data binding 15, joint matrices binding 16); caller must leave those slots empty. The `kModel` write itself also emits the bindless sampler + array, IBL irradiance / prefiltered / lutBRDF, and a per-pipeline device-local materials SSBO built from packed `MaterialShaderData` with texture CRCs remapped to bindless indices.
- **Rebuild-only pipeline lifecycle.** Pipelines may only be (re)created during a whole-`PipelineManager` reconstruction. `PipelineDescriptorWriter::Write` registers raw `Pipeline*` back-references into `gpTextureManager->mTextureDescriptors` for deferred texture/sampler updates, and the only cleanup is `ClearTextureBindings()` at manager rebuild (`PipelineManager.cpp`, `TextureDescriptors.cpp`) — `Pipeline::Destroy` does **not** unregister. Any out-of-rebuild single-pipeline recreate would replay stale state and duplicate registrations, so there is deliberately no per-pipeline/per-texture recreate API; the settings/device-loss path drops and rebuilds the entire `PipelineManager` (see Graphics AGENTS.md Destroy/Refresh), which re-writes every descriptor set fresh against current handles.
- Three-set layout for model pipelines: Set 0 global (TextureManager), Set 1 shared, Set 2 per-material. Multi-set mode binds Set 0/1 once then rebinds pipeline + Set 2 per material; inner materials share the first material's Set 1 layout.
- Descriptor writer drops Set 0 (global handles them) and routes the rest by shader-reflected set indices, for both graphics and compute pipelines. CRC registrations for lazy/deferred updates occur only on framebuffer 0.
- Compute pipelines opt in to the shared global Set 0 per-shader: `CreateComputePipeline` partitions reflected bindings by set index and uses a 2-set pipeline layout `[global Set 0, per-pipeline Set 1]` when the compute shader declares at least one binding at `layout(set = 1, ...)`. First-party compute shaders carry explicit `set = 0` (globalUniform / mainUniform) and `set = 1` (SSBOs, samplers, storage images) qualifiers on every binding; the legacy single-set path (no explicit `set =`, all bindings default to set 0, `mVkExternalDescriptorSetLayout` nulled after creation so binder + writer treat the pipeline as standalone) remains only for the two `Particles/Particles{Spawn,Update}.comp` shaders.
- Bindless texture arrays exported with `UINT32_MAX` sentinel, rewritten to actual count at layout creation.
- Bind-time set indexing: the per-pipeline set uses the framebuffer index only for per-command-buffer pipelines — `mbPerCommandBuffer`, set in `Pipeline::Create` when any `pDescriptorInfos` entry carries `kPerCommandBuffer{Uniform,Storage}Buffers` (host-visible indirect buffers also force it) — else slot 0. Global Set 0 is framebuffer-indexed (`iCommandBuffer`) on the compute path (`BindComputeDescriptorSets`), the indirect-graphics path (`RecordDrawIndirect`), and the multi-set model / UI-depth-prepass prologues (`ModelPipeline.cpp`, `CommandBufferRecordMain.cpp`); on the plain-draw graphics path (`RecordDraw` / `RecordBindPipelineAndDescriptors` → `BindGraphicsDescriptorSets`) Set 0 shares Set 1's single `mbPerCommandBuffer ? iCommandBuffer : 0` index, so a `!mbPerCommandBuffer` plain draw binds `mGlobalDescriptorSets[0]` into every framebuffer's CB — the doc's old "Set 0 always framebuffer-indexed" was an overstatement of this path. Safe, not a bug: the only per-framebuffer-divergent Set-0 content is the global/main UBOs (bindings 0/1, written per-index in `TextureDescriptors::WriteGlobalDescriptorSets`; the samplers + bindless array are identical across framebuffers), and every pipeline that consumes those UBOs declares them in `pDescriptorInfos` with `kPerCommandBufferUniformBuffers`, which forces `mbPerCommandBuffer = true` — so a UBO-reading pipeline always gets `iCommandBuffer` for Set 0. The slot-0 fallback is reachable only by a pipeline declaring no per-command-buffer descriptor, which samples just the framebuffer-invariant Set-0 bindings. **Footgun:** never declare the global/main UBO with plain `kUniformBuffer` on a plain-draw pipeline (it would be `!mbPerCommandBuffer` and bind stale per-frame UBOs into all frames in flight), and don't unify the plain-draw path to `iCommandBuffer` without preserving this coupling. Compute bind logic is exported as a free function (`BindComputeDescriptorSets`) so external record sites apply the same rule.
- Bindless array consumers (descriptor entries flagged at pipeline-create as backed by an array whose slots are populated lazily by a data subsystem, e.g. IslandTerrain) skip the per-CRC `TextureBinding` snapshot — at create time every slot still points at the slot-0 placeholder (the bindless-array init state owned by [../Managers/AGENTS.md](../Managers/AGENTS.md)), so a snapshot would clobber live per-slot bindings on any later sampler-recreate. They register on a separate per-array-pointer map that sampler-recreate reads through the live array pointer instead. Any array consumer that mutates its backing storage in place after pipeline-create must use this flag.
- Per-pipeline `UPDATE_AFTER_BIND` array bindings (`descriptorCount > 1`) on Set 1/Set 2 also get `VK_DESCRIPTOR_BINDING_PARTIALLY_BOUND_BIT` in `ConfigureUpdateAfterBind`. Required for the island bindless terrain arrays whose evicted slots hold the slot-0 placeholder until re-mint; inert on fully-populated arrays since the flag only relaxes validity and never changes output. Mirrors the Set-0 global `pTextures[]` array, which carries the same flag pair. The flag relaxes *validity*, not *liveness*: a Set-1 element must still reference a live view, which is exactly why the **eviction symmetry invariant** ([../Managers/AGENTS.md](../Managers/AGENTS.md)) rewrites a freed slot's element back to the placeholder rather than leaving the evicted quad to zero-width culling.

## Buffer Staging Modes

Three mutually-exclusive modes: persistent host-mapped (CPU-written each frame), device-local (one-shot staging copy at create), and copy-every-frame (both buffers retained, barriers bracket the copy). VMA classifies host-visible requests by usage: readback (transfer-dst only, random host access), indirect, or upload (VMA may substitute device-local + staging). Graphics draw-indirect buffers force host-visible/coherent with no transfer fallback because the GPU reads them directly, with a slot count of `max(framebufferCount, 3)` for resize robustness (CPU rewrites per-template `instanceCount` each frame). Compute dispatch-indirect buffers come in two variants: device-local single-slot (always read at offset 0, written by the GPU — the legacy gated-dispatch path), or host-visible/coherent per-framebuffer (`max(framebufferCount, 3)` slots, CPU-written each frame via `Pipeline::WriteIndirectComputeBuffer`) for passes that size the dispatch dynamically — `kPipelineWaterDisplacement` uses the host-visible variant to write real per-frame workgroup dims (a `VkDispatchIndirectCommand`) into the persistent map, indexed by command-buffer slot just like the graphics indirect path. The slot count bounds the indexed `Record*Indirect` slot at record time.

## Pipeline Creation

- Viewport uses negative height (`VK_KHR_maintenance1`) to flip Y to DirectX convention; front face is therefore counter-clockwise.
- Single-attachment pipelines using the lighting render pass auto-upgrade to 3 color attachments with replicated blend state.
- Vertex input comes from shader reflection: stride is asserted equal to any bound vertex buffer's; reflected stride with no buffer at create makes a per-draw vertex-buffer pipeline (caller binds buffers and draws at record time — per-island terrain meshes); stride 0 means no vertex input (fullscreen passes).
- Push-constant range size defaults to `sizeof(shaders::PushConstantsLayout)` (16 bytes). Pipelines whose shader declares a smaller push-constant block must set the override in `PipelineInfo`; a mismatch (declared range wider than the shader's block) triggers a `BestPractices-PushConstants` validation warning. Every `Pipeline::Record*` method asserts the default range before invoking the shared push helper (which always writes the full 16-byte layout); a smaller-range pipeline must push its own constants directly instead of going through `Record*` (e.g. the lighting-combine compute pass).
- **Trust-boundary validation**: `ModelPipeline::Create` bounds the index/material alias-walk extent against `ChunkHeader::iSize`; `PipelineDescriptorWriter` bounds per-material texture-index fields against `uiTextureCount` before indexing the texture-CRC array. Out-of-range throws `common::CorruptStreamException`.
- See [../Managers/AGENTS.md](../Managers/AGENTS.md) for the pipeline recreation invariant affecting descriptor writes.

## Texture Lifecycle

- Layout transitions driven by a single `kLayoutMappings` table mapping enum to `(layout, access, stage)` — the sole source of truth.
- Lazy path borrows a placeholder view with null image; destroy early-returns in that state so the borrowed view is never freed. Real GPU image swapped in post-upload.
- Transfer-queue to graphics-queue ownership transfer has a fast path when the device reports it optional.
- Transparent material detection drives auto alpha-blend in `ModelPipeline` for non-shadow passes; a record-time draw-pass filter lets opaque and transparent materials draw in separate passes. Push-constant `.w` is reserved as the material-index channel (asserted zero on entry, written per material).
- Demand-loading: non-indirect pipelines request textures immediately at create; indirect pipelines defer until first non-empty indirect write (latched).
- Generation counter: every handle swap (create, transfer-adopt) bumps a monotonic per-Texture generation; move-construct preserves it and destroy does NOT reset. Descriptor-binding sites snapshot the generation alongside the texture pointer so `PipelineManager` can assert at command-buffer record time that no cached binding still points at a recycled handle.
