# `/Engine/Source/Network/` - Networking

See also: [Network Architecture](../../../Documents/Architecture/Network.md)

## Overview

Provides client/server networking infrastructure using the ENet reliable UDP library. NetworkManager is a singleton (`gpNetworkManager`) that owns the ENet library lifecycle and defines the slot-based channel layout. NetworkServer and NetworkClient handle the server-side and client-side communication respectively, using a custom binary protocol defined in NetworkProtocol. NetworkSerialization handles compact binary serialization and LZ4 compression of game state for network transmission. Used by both client and server builds.

## Key Classes/Systems

- **NetworkManager** - Singleton managing ENet library initialization and shutdown. Defines the slot-based ENet channel layout: channel 0 is control reliable (handshake, subscribe/unsubscribe, spawn, assign, desync), channel 1 is control unreliable (reserved), and channels 2+ are paired reliable/unreliable per coord slot. Up to 11 coord slots (10 active + 1 spare for grid transition overlap) yield 24 total ENet channels. Static helpers `CoordSlotReliable()`/`CoordSlotUnreliable()` map slot indices to channel numbers, `ChannelToSlot()` maps channels back, `IsCoordChannel()` distinguishes coord channels from control channels, and `IsUnreliableChannel()` identifies any unreliable channel (control unreliable or odd-numbered coord channel) for network simulation filtering. Constructed in `Main.cpp` for both client and server builds.

- **NetworkProtocol** - Defines the wire protocol: `PacketType` enum for all packet types (server assign/coord-full-state/coord-update/coord-resend/subscribe-accept/unsubscribe-ack/debug-frame/connection-response/player-state, client ack-stream/spawn/desync/debug-frame-request/hello/subscribe/unsubscribe), `PlayerStateType` enum for server-authoritative player state transitions (kSpawned, kChangedFrame, kDied) sent via `kServerPlayerState`, `ClientRequestFlags` for spawn/respawn requests, protocol constants (default port, max resend frames, max buffered frames, max packet size, max status changes per cell, max missing frames), LAN discovery constants (discovery port, magic value, scan timeout), and network simulation infrastructure. The `DelayedPacket` struct holds a release timestamp, copied packet data, and optional peer pointer for deferred delivery. The `NetworkSimulation` namespace provides `ShouldDrop()` (stateful burst-based packet loss: initial drop probability from `kfSimulatedPacketLossPercent`, then 50% continuation probability during a burst, capped at half of `kiMaxMissingFrames` consecutive drops), `RandomOneWayDelay()` (random one-way latency between half of `kiSimulatedPingMinMs` and half of `kiSimulatedPingMaxMs`), and a simple LCG `Random01()`. Simulation constants are applied per-direction (receive side), so the configured ping range represents the full round-trip added latency.

- **NetworkServer** (`gpNetworkServer`, `Network/NetworkServer/` subfolder) - Split across three `.cpp` files sharing a single `.h`: `NetworkServer.cpp` (core lifecycle, polling, buffering, utilities), `NetworkServerReceive.cpp` (Handle* methods for incoming packets), `NetworkServerSend.cpp` (Send* methods for outgoing packets). Server-side ENet host managing client connections. Configures 1MB socket send and receive buffers to handle bursty packet traffic. Disables ENet peer throttle on each connecting client to prevent unreliable packet drops during reconciliation stalls. Implements a build config handshake: on connect, waits for a `kClientHello` packet containing the client's `kpcBuildConfigName`; validates it matches the server's build config and sends a `kServerConnectionResponse` (accept or reject with reason message); on mismatch, calls `RemoveClient()` and schedules a deferred disconnect. Uses slot-based coord subscriptions: each `ClientConnection` has an array of `ClientCoordSubscription` slots (up to `kiMaxCoordSlots`) with per-slot `PerCoordAckState` (independent ACK floor + 64-bit received bitfield + epoch counter for slot reuse protection). The client drives subscriptions via `kClientSubscribe`/`kClientUnsubscribe` packets; the server allocates/frees slots and confirms via `SendSubscribeAccept()`/`SendUnsubscribeAck()`. `ComputeActiveSetServer()` in the game layer unions all clients' subscribed coords. `HandleClientSubscribe()` allocates a slot, activates it, resets its ACK state, increments the slot's epoch, and sends an accept (with epoch); `HandleClientUnsubscribe()` frees the slot (preserving epoch) and sends an ack. Handles incoming client ACK streams (per-slot acknowledgment state and RTT timestamp), spawn requests, desync reports (logged via `common::Log` with `common::ToHex` for CRC values), and debug frame requests (responds with a buffered full serialized frame snapshot for desync diagnosis via `CompressToBuffer()`). On disconnect, captures the disconnecting client's player ID and grid coordinate into a `PendingDisconnect` before calling `RemoveClient()`, enabling the game layer to inject destroy StatusChanges for cleanup. `FindClient()` is a public method (with const and mutable overloads) that looks up a `ClientConnection` by client ID, used by the game layer for server-side operations like spawn request handling and subscription updates. `RemoveClient()` is a private helper that performs swap-and-pop removal from the client vector, used by both `HandleDisconnect()` and `HandleClientHello()` (on build mismatch rejection). Stores per-slot ACK state received from client ACK stream packets; each packet carries a variable-length list of per-slot ACK data (slot index, epoch, ACK floor, bitfield). ACK updates are triple-guarded: the slot must be active, the epoch must match the current slot epoch (preventing stale ACK data from a previous subscription on the same slot from corrupting the new subscription's state), and the ACK floor must be monotonically non-decreasing (updates are ignored if the incoming floor is less than the stored floor). When a packet arrives with the same ACK floor as the stored value, the bitfield is OR-merged rather than replaced, preserving acknowledgment bits from earlier packets. Stores per-client pipeline RTT timestamp (`iClientTimestampNs`) received from client ACK stream packets with a monotonic guard (only updates if the incoming timestamp exceeds the stored value, preventing out-of-order packets from regressing the timestamp), and echoes it back in `SendUpdate()` packets, enabling the client to measure full pipeline round-trip time. Sends player assignment (via control reliable channel), player state notifications (`SendPlayerState()` via control reliable channel, carrying the state type, player ID, and grid coord for server-authoritative state transitions including spawn, frame change, and death), per-coord full state (LZ4-compressed Frame serialization via the slot's reliable channel), debug frame snapshots, and per-coord delta updates. `SendCoordFullState()` sends a full state for a single coord on the coord slot's reliable channel, including the slot index, slot epoch, frame number, coord, and LZ4-compressed serialized frame via `CompressToBuffer()`. `CompressToBuffer()` is a private method that LZ4-compresses data into the persistent `mCompressionBuffer`, growing it as needed; used by `SendCoordFullState()`, `HandleClientDebugFrameRequest()`, and `BufferFrame()`. `SendUpdate()` and `SendResends()` use `FindBufferedFrame()` to look up per-coord ring buffer entries by coordinate and frame number, computing the index directly from the frame offset relative to the buffer front. `SendUpdate()` and `SendResends()` both use `WriteBufferedFramePacket()` to assemble the packet payload (type, slot index, epoch, frame number, echoed timestamp, CRC, input CRC, and compressed status changes); the epoch is read from the slot's current `PerCoordAckState` so the client can validate it matches the active subscription. `SendUpdate()` iterates each active subscription slot, finds the coord's buffered data for the current frame, and sends one unreliable packet per active slot on the slot's unreliable channel. `SendResends()` iterates each active subscription slot using the slot's per-coord ACK state: scans unset bits above the ACK floor up to the highest set bit via `std::bit_width` (avoiding spurious resends of in-transit frames beyond the ACK frontier), looks up the missing frame via `FindBufferedFrame()`, and sends each re-sent frame as its own separate unreliable `kServerCoordResend` packet on the slot's unreliable channel. `BufferFrame()` populates per-coord ring buffers (keyed by `GridCoord`) once per frame with unfiltered data (CRC, input CRC, compressed status changes) for re-send support; reuses `mCompressionBuffer` for status change compression. `BufferFullFrame()` stores a separate ring buffer of fully serialized frame snapshots per grid coordinate for responding to debug frame requests. `Flush()` calls `enet_host_flush` to immediately dispatch all queued outgoing packets without waiting for the next `enet_host_service` call, ensuring per-physics-frame updates are sent promptly when multiple physics frames run per tick. Provides both const and mutable `GetClients()` accessors so the game layer can iterate clients for per-client operations. `Poll()` clears three pending vectors (`mPendingSpawnRequests`, `mPendingDisconnects`, `mPendingNewSubscriptions`) at the start of each call, then processes ENet events. `DrainPendingDisconnects()` exposes pending disconnects alongside `DrainPendingSpawnRequests()`, and `DrainPendingNewSubscriptions()` (which the game layer uses to send full state for newly subscribed coords via `SendCoordFullState()`). When `kbEnableNetworkSimulation` is enabled, received unreliable packets (detected by channel: control unreliable or odd-numbered coord channel) are subject to random drop and random delay via a `DelayedPacket` deque: dropped packets are discarded, surviving packets are inserted in sorted order by release time (via `lower_bound`) into a `DelayedPacket` deque, and `Poll()` drains matured packets before processing ENet events. Logs one-time, rare, and error-condition network events via `common::Log` (connection, disconnection, build config handshake, desync reports, debug frame responses).

- **NetworkClient** (`gpNetworkClient`, `Network/NetworkClient/` subfolder) - Split across three `.cpp` files sharing a single `.h`: `NetworkClient.cpp` (core lifecycle, polling, ACK tracking), `NetworkClientReceive.cpp` (Handle* methods, DecompressAndReadFrame), `NetworkClientSend.cpp` (Send* methods). Client-side ENet peer connecting to a server. Configures 1MB socket send and receive buffers to handle bursty packet traffic. Disables ENet peer throttle on the server peer to prevent unreliable packet drops during reconciliation stalls. On ENet connect, automatically sends a `kClientHello` packet containing the client's `kpcBuildConfigName` for build config validation. Tracks connection acceptance state: `IsConnectionAccepted()` returns true after receiving an accepted `kServerConnectionResponse`; `GetRejectionReason()` returns the server's rejection message (or nullptr if not rejected). The game layer polls these to gate entry into gameplay and display error modals on rejection. Uses slot-based coord subscriptions: maintains an array of `ClientCoordSlot` (up to `kiMaxCoordSlots`), each with a `CoordSubscriptionState` (kUnsubscribed, kSubscribing, kWaitingFullState, kActive, kUnsubscribing) and epoch for slot reuse protection. The game layer drives subscriptions via `SendSubscribe(coord)` and `SendUnsubscribe(slot)`, which send reliable packets and transition states. `SendSubscribe()` can reuse slots in kUnsubscribed or kUnsubscribing state (allowing subscription of a new coord before the unsubscribe ack arrives for an old one); when reusing a kUnsubscribing slot, it purges delayed packets for that slot's channels (when network simulation is enabled) to prevent stale data from the old subscription from being processed after the new subscription begins. `HandleServerSubscribeAccept()` transitions the slot to kWaitingFullState and stores the server-provided epoch; `HandleServerCoordFullState()` transitions from kWaitingFullState, kSubscribing, or kUnsubscribed to kActive, initializes the slot's ACK floor, and stores the epoch from the full state packet. For slots in kWaitingFullState or kSubscribing state, the handler validates that the packet's coord matches the slot's coord, silently discarding mismatches to prevent stale full state from a previous subscription from corrupting the slot on rapid unsub/resub. The kUnsubscribed case handles cross-channel ordering where the full state (sent on the coord slot's reliable channel) arrives before the subscribe accept (sent on the control reliable channel); when this happens, the handler calls `ClearSubscribingPlaceholder()` to find and reset the kSubscribing placeholder at the original slot, then adopts the server-assigned slot. Full state decompression uses the `DecompressAndReadFrame()` static helper (shared with `HandleServerDebugFrame()`), which reads uncompressed/compressed sizes, LZ4-decompresses, and deserializes via `ServerRead()`. `HandleServerUnsubscribeAck()` resets the slot to kUnsubscribed. Each slot has independent ACK tracking (ACK floor + 64-bit received bitfield) for its subscribed coord. `TrackReceivedFrame()` operates per-slot, advancing the floor as contiguous bits are consumed. Also sends spawn requests, subscribe/unsubscribe requests, desync reports, and debug frame requests. The server echoes the RTT timestamp back in update packets and the client computes the smoothed round-trip time using a monotonic guard on the echoed timestamp to prevent out-of-order echo processing (exposed via `GetPipelineRttUs()`). Called from `Main.cpp` before `Flush()` to ensure the most up-to-date ACK state is dispatched. `SendAck()` sends a `kClientAckStream` packet containing per-slot ACK state (a variable-length list of slot index, epoch, ACK floor, and bitfield for each active slot) and a `high_resolution_clock` nanosecond timestamp for pipeline RTT measurement. Receives player assignments (accumulated into a `ReceivedAssignment` vector drained by the game layer via `DrainReceivedAssignments()`; supports multiple assignments per poll cycle, e.g., during rapid grid transfers), server-authoritative player state notifications (`kServerPlayerState` parsed into `ReceivedPlayerState` structs carrying the state type, player ID, and grid coord, accumulated into a vector drained by the game layer via `DrainReceivedPlayerStates()`), per-coord full state snapshots (LZ4-decompressed into `ReceivedCoordFullState` objects including slot index for subscription state management via `ServerRead()` to handle server-format streams that exclude client-only fields), per-coord delta update streams (`kServerCoordUpdate` parsed per-slot with epoch, CRC, input CRC (both read as uint64), and compressed status changes, accumulated into per-slot `ReceivedCoordUpdate` vectors), per-coord re-send streams (`kServerCoordResend` packets parsed identically to update streams via a shared `HandleServerCoordUpdateOrResend()` method; both update and resend handlers accept packets for kActive or kWaitingFullState slots (with matching epoch), silently discarding packets for other states or stale epochs; updates received while in kWaitingFullState are buffered but skip ACK tracking to avoid triggering missing-frame disconnects before the full state arrives), and debug frame responses (deserialized into a `ReceivedDebugFrame` for the game layer to compare). `DrainReceivedCoordUpdates()` exposes the per-slot update arrays; `DrainReceivedFullStates()` exposes full state receptions. `GetCoordSlots()` exposes subscription state for external queries (used by the game layer for subscription management and the profile overlay). Tracks per-tick bandwidth via host-level cumulative counters with `InTheLastSecond` smoothing (exposed via `GetBytesInPerSecond()` and `GetBytesOutPerSecond()`). Supports a desync debug mode (`SetDesyncDebugMode()`) that suppresses frame gap tracking in `TrackReceivedFrame()`, preventing incoming frames from triggering "Too many missing frames" disconnects while waiting for a debug frame response. Provides `Disconnect()` for graceful mid-session disconnect without destroying the client object. Exposes `WasDisconnected()` to detect server-initiated disconnects (set once on disconnect event, never cleared). `DrainReceivedDebugFrame()` moves the received debug frame to the caller via unique_ptr transfer. `Flush()` calls `enet_host_flush` to immediately dispatch all queued outgoing packets without waiting for the next `enet_host_service` call, same pattern as `NetworkServer::Flush()`. When `kbEnableNetworkSimulation` is enabled, received unreliable packets are subject to random drop and random delay via a `DelayedPacket` deque (same pattern as NetworkServer). Logs one-time, rare, and error-condition network events via `common::Log` (connection, disconnection, desync reports, debug frame responses).

- **NetworkDiscovery** - LAN server discovery using UDP broadcast. `NetworkDiscoveryResponder` (server-only) listens on a dedicated UDP port and replies with a magic value when queried. `NetworkDiscoveryScanner` (client-only) broadcasts a discovery probe to localhost and LAN, then polls for a response within a configurable timeout. On success, provides the server's IP address for automatic connection.

- **NetworkCursor** (`NetworkCursor.h`) - Shared inline cursor-based binary read/write helpers used across all Network*.cpp files. Provides typed readers (`ReadUint8`, `ReadUint16`, `ReadInt32`, `ReadUint32`, `ReadInt64`, `ReadUint64`, `ReadFloat`, `ReadVec4`, `ReadGridCoord`) and writers (`WriteUint8`, `WriteUint16`, `WriteInt32`, `WriteUint32`, `WriteInt64`, `WriteUint64`, `WriteFloat`, `WriteVec4`) plus raw `ReadBytes`/`WriteBytes`. All operate on a `uint8_t*&` cursor that auto-advances.

- **NetworkSerialization** (free functions) - Type-specific binary serialization of `game::StatusChange` batches for network transport. Groups changes by `StatusChangeType`, then serializes each group with a type+count header followed by per-type field layouts (blaster, spaceship, missile, player transfers, and player destroys). Player destroy changes serialize the player ID packed into 8 bytes of the position vector. Uses NetworkCursor helpers for compact wire format. Compress/decompress variants add LZ4 compression with a 4-byte uncompressed-size prefix. Uses the workbuffer for intermediate storage during serialization and compression passes. Missile transfers always write/read 8 bytes for the smoke trail ID regardless of build (server writes 0, client writes actual value) to maintain consistent wire format across builds.

## Architecture Notes

**Channel Layout and Slot-Based Subscriptions**: ENet channels are organized as: channel 0 (control reliable), channel 1 (control unreliable, reserved), then pairs of reliable/unreliable channels per coord slot (channels 2-23). Each coord slot maps to exactly one `GridCoord` the client is subscribed to. The client drives subscriptions by sending `kClientSubscribe` (with desired coord) and `kClientUnsubscribe` (with slot index); the server allocates/frees slots and replies with `kServerSubscribeAccept`/`kServerUnsubscribeAck`. Up to 11 slots (10 active + 1 spare for overlap during grid transitions) allow seamless migration between grid cells. Full state for newly subscribed coords is sent on the slot's reliable channel; delta updates and resends use the slot's unreliable channel. Per-slot ACK tracking gives each coord independent frame tracking, preventing one coord's packet loss from stalling others.

**Connection Handshake**: After ENet connect, the client sends a `kClientHello` with its `kpcBuildConfigName`; the server validates the config matches and replies with `kServerConnectionResponse` (accept/reject). The client blocks game entry until acceptance; on rejection, the game layer shows the rejection reason in a modal dialog and disconnects.

**Data Flow**: The server broadcasts per-coord delta updates (compressed StatusChange batches) each tick to connected clients via their subscription slots. AI decisions are computed deterministically from frame state on both client and server, so player inputs are not included in the wire protocol. Broadcasting is a two-step process: `BufferFrame()` compresses and stores unfiltered data (including both frame CRC and input CRC) into per-coord ring buffers once per frame, then `SendUpdate()` iterates each client's active subscription slots and sends one unreliable packet per slot. Full state transfers use LZ4-compressed Frame serialization and are sent when a subscription is established. Both server and client use the workbuffer for packet assembly and NetworkCursor's inline binary read/write helpers for deserialization.

**Re-send Support**: Uses a proactive ACK-based system with per-slot independence and epoch-based slot reuse protection. Each client coord slot has its own ACK floor (highest contiguously received frame), 64-bit bitfield for out-of-order frames above the floor, and epoch counter. This per-slot ACK state is sent in dedicated `kClientAckStream` packets as a variable-length list of (slot index, epoch, floor, bitfield) tuples. The server reads each slot's ACK state, validates the epoch matches the current slot epoch (preventing stale ACK data from a previous subscription on the same slot from triggering invalid resends), and scans unset bits above the floor (up to the highest set bit via `std::bit_width` to avoid resending frames still in transit), looking up the coord's per-coord ring buffer for missing frame data. Re-sends are sent as separate `kServerCoordResend` unreliable packets on the slot's unreliable channel (one per missing frame per slot), keeping re-send traffic isolated from current-frame updates.

**Pipeline RTT Measurement**: The client embeds a nanosecond timestamp in each ACK stream packet; the server stores the latest per-client timestamp and echoes it in the next update packet header; the client computes the round-trip time and smooths it for stable readout on the profile overlay. This measures full pipeline latency (client send -> server process -> server broadcast -> client receive) rather than just ENet's transport-level RTT.

**Debug Frame Diagnostics**: When the client detects a CRC mismatch during reconciliation, it can request the server's full serialized frame via `SendDebugFrameRequest()`. The server maintains a separate ring buffer of full frame snapshots (`BufferFullFrame()`) and responds with the matching frame data. The client receives it as a `ReceivedDebugFrame` for per-component CRC comparison in the game layer.

**Network Simulation**: When `kbEnableNetworkSimulation` is enabled (controlled by a compile-time constant in `Pch.h` per build configuration), both NetworkClient and NetworkServer inject simulated packet loss and variable latency on received unreliable packets. On receive, each unreliable packet is dropped via a stateful burst model (initial drop probability then continuation probability during a burst, capped to prevent exceeding the missing frame limit) or inserted in sorted order by release time (via `lower_bound`) into a `DelayedPacket` deque with a random one-way delay (half the configured ping range). At the start of each `Poll()`, matured delayed packets are drained from the front and processed before new ENet events. Reliable packets bypass simulation entirely. The simulation operates per-direction (both client and server apply it independently on their receive paths), so the effective added round-trip latency is the sum of both sides' delays. On disconnect, the server purges all delayed packets for the disconnecting peer; on unsubscribe ack, the client purges delayed packets for the unsubscribed slot's channels. Controlled by compile-time `if constexpr` for zero overhead when disabled.
