# `/Engine/Source/Network/` - Networking

See also: [Network Architecture](../../../Documents/Architecture/Network.md)

## Overview

Provides client/server networking infrastructure using the ENet reliable UDP library. NetworkManager is a singleton (`gpNetworkManager`) that owns the ENet library lifecycle. NetworkServer and NetworkClient handle the server-side and client-side communication respectively, using a custom binary protocol defined in NetworkProtocol. NetworkSerialization handles compact binary serialization and LZ4 compression of game state for network transmission. Used by both client and server builds.

## Key Classes/Systems

- **NetworkManager** - Singleton managing ENet library initialization and shutdown. Defines channel constants for reliable and unreliable communication. Constructed in `Main.cpp` for both client and server builds.

- **NetworkProtocol** - Defines the wire protocol: `PacketType` enum for all packet types (server assign/full-state/update-stream/resend-stream/debug-frame/connection-response, client input/spawn/desync/debug-frame-request/hello), `ClientRequestFlags` for spawn/respawn requests, protocol constants (default port, max resend frames, max buffered frames, max packet size), LAN discovery constants (discovery port, magic value, scan timeout), and network simulation infrastructure. The `DelayedPacket` struct holds a release timestamp, copied packet data, and optional peer pointer for deferred delivery. The `NetworkSimulation` namespace provides `ShouldDrop()` (stateful burst-based packet loss: initial drop probability from `kfSimulatedPacketLossPercent`, then 50% continuation probability during a burst, capped at half of `kiMaxMissingFrames` consecutive drops), `RandomOneWayDelay()` (random one-way latency between half of `kiSimulatedPingMinMs` and half of `kiSimulatedPingMaxMs`), and a simple LCG `Random01()`. Simulation constants are applied per-direction (receive side), so the configured ping range represents the full round-trip added latency.

- **NetworkServer** (`gpNetworkServer`) - Server-side ENet host managing client connections. Configures 1MB socket send and receive buffers to handle bursty packet traffic. Disables ENet peer throttle on each connecting client to prevent unreliable packet drops during reconciliation stalls. Implements a build config handshake: on connect, waits for a `kClientHello` packet containing the client's `kpcBuildConfigName`; validates it matches the server's build config and sends a `kServerConnectionResponse` (accept or reject with reason message); on mismatch, removes the client and schedules a deferred disconnect. Tracks each client's active grid region (3x3 around their player plus origin, matching the client's `ComputeActiveSet`), plus `pendingFullStateCoords` (coords needing full state after a subscription change). Handles incoming client input streams (with server-side press detection from held-state deltas and per-tick deduplication that OR-merges pressed flags when multiple packets arrive in one tick), spawn requests, desync reports (logged via `common::Log` with `common::ToHex` for CRC values), and debug frame requests (responds with a buffered full serialized frame snapshot for desync diagnosis). On disconnect, captures the disconnecting client's player ID and grid coordinate into a `PendingDisconnect` before removing the client, enabling the game layer to inject destroy StatusChanges for cleanup. Stores per-client ACK state (ACK floor + 64-bit received bitfield) received from client input packets; the ACK floor is monotonically non-decreasing (updates are ignored if the incoming floor is less than the stored floor) to guard against out-of-order packets regressing the floor. Stores per-client pipeline RTT timestamp (`iClientTimestampNs`) received from client input packets and echoes it back in `SendUpdate()` packets, enabling the client to measure full pipeline round-trip time. Sends player assignment, full state (LZ4-compressed Frame serialization), debug frame snapshots, and per-tick delta updates containing compressed StatusChange batches and player inputs, filtered to each client's active grid cells. `SendUpdate()` sends per-client filtered data as a single unreliable packet for the current frame. `SendResends()` proactively determines unacknowledged frames by scanning unset bits above the client's ACK floor up to the highest set bit in the received bitfield (via `std::bit_width`), avoiding spurious resends of in-transit frames beyond the ACK frontier, and sends each re-sent frame as its own separate unreliable `kServerResendStream` packet (from the ring buffer, containing all grid data for that frame), keeping re-send traffic isolated from current-frame updates. `SendAssignPlayer()` diffs old vs new `activeCoords` and stores only newly-subscribed coords in `pendingFullStateCoords`, enabling delta-based full state sends (the game layer reads `pendingFullStateCoords` to send frames only for coords the client doesn't already have). `GridUpdateData` carries both `statusChanges` and `playerInputs` spans; `BufferFrame()` populates the ring buffer once per frame with unfiltered data (including player inputs) for re-send support; `BufferFullFrame()` stores a separate ring buffer of fully serialized frame snapshots per grid coordinate for responding to debug frame requests. `Flush()` calls `enet_host_flush` to immediately dispatch all queued outgoing packets without waiting for the next `enet_host_service` call, ensuring per-physics-frame updates are sent promptly when multiple physics frames run per tick. Provides both const and mutable `GetClients()` accessors so the game layer can iterate clients for per-client filtering during broadcast. `DrainPendingDisconnects()` exposes pending disconnects alongside `DrainPendingInputs()` and `DrainPendingSpawnRequests()`. When `kbEnableNetworkSimulation` is enabled, received unreliable packets are subject to random drop and random delay via a `DelayedPacket` deque: dropped packets are discarded, surviving packets are queued with a random release time, and `Poll()` drains matured packets before processing ENet events. Logs reliable network events (connect, disconnect, assign player, full state sends, spawn requests, desync reports) via `common::Log`.

- **NetworkClient** (`gpNetworkClient`) - Client-side ENet peer connecting to a server. Configures 1MB socket send and receive buffers to handle bursty packet traffic. Disables ENet peer throttle on the server peer to prevent unreliable packet drops during reconciliation stalls. On ENet connect, automatically sends a `kClientHello` packet containing the client's `kpcBuildConfigName` for build config validation. Tracks connection acceptance state: `IsConnectionAccepted()` returns true after receiving an accepted `kServerConnectionResponse`; `GetRejectionReason()` returns the server's rejection message (or nullptr if not rejected). The game layer polls these to gate entry into gameplay and display error modals on rejection. Sends player input, spawn requests, desync reports, and debug frame requests (requesting the server's full serialized frame at a specific frame number and grid coordinate for desync diagnosis). Each input packet embeds a `high_resolution_clock` nanosecond timestamp for pipeline RTT measurement; the server echoes it back in update packets and the client computes the smoothed round-trip time (exposed via `GetPipelineRttUs()`). Receives player assignments (accumulated into a `ReceivedAssignment` vector cleared at the start of each `Poll()` and drained by the game layer via `DrainReceivedAssignments()`; supports multiple assignments per poll cycle, e.g., during rapid grid transfers), full state snapshots (LZ4-decompressed into Frame objects via `ServerRead()` to handle server-format streams that exclude client-only fields, with decompression failure logging and skipping), delta update streams (decompressed StatusChange batches and player inputs per grid cell with CRC for desync detection), separate re-send streams (`kServerResendStream` packets, each containing a single re-sent frame's grid data parsed identically to update streams), and debug frame responses (deserialized into a `ReceivedDebugFrame` for the game layer to compare). Tracks received frames using an ACK floor (highest contiguously received frame number) and a 64-bit bitfield for out-of-order frames above the floor; the floor advances automatically as contiguous bits are consumed. `GetAckFloor()`, `GetReceivedBitfield()`, and `GetServerPeer()` expose connection and ACK state for external queries (used by the profile overlay's Network screen). Tracks per-tick bandwidth via host-level cumulative counters with `InTheLastSecond` smoothing (exposed via `GetBytesInPerSecond()` and `GetBytesOutPerSecond()`). ACK state is piggybacked onto every input packet so the server can proactively determine which frames need re-sending. Supports a desync debug mode (`SetDesyncDebugMode()`) that suppresses frame gap tracking in `TrackReceivedFrame()`, preventing incoming frames from triggering "Too many missing frames" disconnects while waiting for a debug frame response. Warns and triggers a debug break when the frame gap reaches `kiMaxMissingFrames`, then disconnects. Bitfield writes are guarded to `iBitIndex < 64`; frames beyond the bitfield range are logged but not tracked. Full state receptions establish the ACK floor on initial connection only (when the floor is uninitialized); subsequent full states from subscription updates do not jump the floor, preventing falsely acknowledging unreceived frames between the old floor and the full state frame. Provides `Disconnect()` for graceful mid-session disconnect without destroying the client object. Exposes `WasDisconnected()` to detect server-initiated disconnects (set once on disconnect event, never cleared). `DrainReceivedDebugFrame()` moves the received debug frame to the caller via unique_ptr transfer. `Flush()` calls `enet_host_flush` to immediately dispatch all queued outgoing packets without waiting for the next `enet_host_service` call, same pattern as `NetworkServer::Flush()`. Called from `Main.cpp` after `SendNetworkInput()` (which itself follows physics, poll, and kick) to immediately dispatch input packets carrying the most up-to-date ACK state. When `kbEnableNetworkSimulation` is enabled, received unreliable packets are subject to random drop and random delay via a `DelayedPacket` deque (same pattern as NetworkServer): dropped packets are discarded, surviving packets are queued with a random release time, and `Poll()` drains matured packets before processing ENet events. Logs reliable network events (connect, disconnect, assign player, full state receives, spawn requests, desync reports) via `common::Log`.

- **NetworkDiscovery** - LAN server discovery using UDP broadcast. `NetworkDiscoveryResponder` (server-only) listens on a dedicated UDP port and replies with a magic value when queried. `NetworkDiscoveryScanner` (client-only) broadcasts a discovery probe to localhost and LAN, then polls for a response within a configurable timeout. On success, provides the server's IP address for automatic connection.

- **NetworkSerialization** (free functions) - Type-specific binary serialization of `game::StatusChange` batches for network transport. Groups changes by `StatusChangeType`, then serializes each group with a type+count header followed by a per-entry `uiSequence` number (for deterministic ordering on the receiving end) and per-type field layouts (blaster, spaceship, missile, player transfers, and player destroys). Player destroy changes serialize the player ID packed into 8 bytes of the position vector. Uses cursor-based read/write helpers for compact wire format. Compress/decompress variants add LZ4 compression with a 4-byte uncompressed-size prefix. Uses the workbuffer for intermediate storage during serialization and compression passes. Missile transfers always write/read 8 bytes for the smoke trail ID regardless of build (server writes 0, client writes actual value) to maintain consistent wire format across builds.

## Architecture Notes

Connection establishment uses a build config handshake: after ENet connect, the client sends a `kClientHello` with its `kpcBuildConfigName`; the server validates the config matches and replies with `kServerConnectionResponse` (accept/reject). The client blocks game entry until acceptance; on rejection, the game layer shows the rejection reason in a modal dialog and disconnects. The server broadcasts delta updates (compressed StatusChange batches and player inputs) each tick to connected clients, filtered to each client's active grid region (3x3 plus origin). Player inputs are echoed back from server to client alongside status changes to ensure physics determinism -- the client applies server-authoritative inputs rather than locally-generated ones. Broadcasting is a two-step process: `BufferFrame()` compresses and stores unfiltered data (including player inputs) into the ring buffer once per frame, then `SendUpdate()` is called per-client with data filtered by the game layer. Full state transfers use LZ4-compressed Frame serialization and are sent on initial connect or when a client's active region changes; delta-based optimization sends only newly-subscribed coords (not overlapping ones the client already has), reducing bandwidth by ~67% for cardinal grid moves and ~44% for diagonal moves. Both server and client use the workbuffer for packet assembly and cursor-based binary read/write helpers for deserialization. Re-send support uses a proactive ACK-based system: the client tracks an ACK floor (highest contiguously received frame) and a 64-bit bitfield for out-of-order frames above the floor, piggybacking this ACK state onto every input packet. The server reads each client's ACK state and proactively determines which frames are missing (unset bits above the ACK floor, scanning only up to the highest set bit via `std::bit_width` to avoid resending frames still in transit). Re-sends are sent as separate `kServerResendStream` unreliable packets (one per missing frame) via `SendResends()`, keeping re-send traffic isolated from the current frame's `SendUpdate()` packet. This separation prevents re-send data from inflating current-frame packets and allows the OS/network to handle each packet independently. Pipeline RTT measurement: the client embeds a nanosecond timestamp in each input packet; the server stores the latest per-client timestamp and echoes it in the next update packet header; the client computes the round-trip time and smooths it for stable readout on the profile overlay. This measures full pipeline latency (client send -> server process -> server broadcast -> client receive) rather than just ENet's transport-level RTT. Debug frame diagnostics: when the client detects a CRC mismatch during reconciliation, it can request the server's full serialized frame via `SendDebugFrameRequest()`. The server maintains a separate ring buffer of full frame snapshots (`BufferFullFrame()`) and responds with the matching frame data. The client receives it as a `ReceivedDebugFrame` for per-component CRC comparison in the game layer. Network simulation: when `kbEnableNetworkSimulation` is enabled (controlled by a compile-time constant in `Pch.h` per build configuration), both NetworkClient and NetworkServer inject simulated packet loss and variable latency on received unreliable packets. On receive, each unreliable packet is dropped via a stateful burst model (initial drop probability then continuation probability during a burst, capped to prevent exceeding the missing frame limit) or queued into a `DelayedPacket` deque with a random one-way delay (half the configured ping range). At the start of each `Poll()`, matured delayed packets are drained and processed before new ENet events. Reliable packets bypass simulation entirely. The simulation operates per-direction (both client and server apply it independently on their receive paths), so the effective added round-trip latency is the sum of both sides' delays. Controlled by compile-time `if constexpr` for zero overhead when disabled.
