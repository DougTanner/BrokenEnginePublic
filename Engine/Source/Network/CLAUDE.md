# `/Engine/Source/Network/` - Networking

## Overview

Provides client/server networking infrastructure using the ENet reliable UDP library. NetworkManager is a singleton (`gpNetworkManager`) that owns the ENet library lifecycle. NetworkServer and NetworkClient handle the server-side and client-side communication respectively, using a custom binary protocol defined in NetworkProtocol. NetworkSerialization handles compact binary serialization and LZ4 compression of game state for network transmission. Used by both client and server builds.

## Key Classes/Systems

- **NetworkManager** - Singleton managing ENet library initialization and shutdown. Defines channel constants for reliable and unreliable communication. Constructed in `Main.cpp` for both client and server builds.

- **NetworkProtocol** - Defines the wire protocol: `PacketType` enum for all packet types (server assign/full-state/update-stream, client input/spawn/desync), `ClientRequestFlags` for spawn/respawn requests, protocol constants (default port, max resend frames, max buffered frames, max packet size), and LAN discovery constants (discovery port, magic value, scan timeout).

- **NetworkServer** (`gpNetworkServer`) - Server-side ENet host managing client connections. Tracks each client's active 3x3 grid region around their player. Handles incoming client input streams (with server-side press detection from held-state deltas and per-tick deduplication that OR-merges pressed flags when multiple packets arrive in one tick), spawn requests, and desync reports (logged via `common::Log` with `common::ToHex` for CRC values). Sends player assignment, full state (LZ4-compressed Frame serialization), and per-tick delta updates containing compressed StatusChange batches and player inputs, filtered to each client's active grid cells. `GridUpdateData` carries both `statusChanges` and `playerInputs` spans; `BufferFrame()` populates the ring buffer once per frame with unfiltered data (including player inputs) for re-send support, while `SendUpdate()` sends per-client filtered data to a single client. Provides both const and mutable `GetClients()` accessors so the game layer can iterate clients for per-client filtering during broadcast. Logs reliable network events (connect, disconnect, assign player, full state sends, spawn requests, desync reports) via `common::Log`.

- **NetworkClient** (`gpNetworkClient`) - Client-side ENet peer connecting to a server. Sends player input, spawn requests, and desync reports. Receives player assignment, full state snapshots (LZ4-decompressed into Frame objects via `ServerRead()` to handle server-format streams that exclude client-only fields), and delta update streams (decompressed StatusChange batches and player inputs per grid cell with CRC for desync detection). Tracks received frame numbers and detects gaps to request re-sends, which are piggybacked onto the input stream packet. Provides `Disconnect()` for graceful mid-session disconnect without destroying the client object. Logs reliable network events (connect, disconnect, assign player, full state receives, spawn requests, desync reports) via `common::Log`.

- **NetworkDiscovery** - LAN server discovery using UDP broadcast. `NetworkDiscoveryResponder` (server-only) listens on a dedicated UDP port and replies with a magic value when queried. `NetworkDiscoveryScanner` (client-only) broadcasts a discovery probe to localhost and LAN, then polls for a response within a configurable timeout. On success, provides the server's IP address for automatic connection.

- **NetworkSerialization** (free functions) - Type-specific binary serialization of `game::StatusChange` batches for network transport. Groups changes by `StatusChangeType`, then serializes each group with a type+count header followed by per-type field layouts (blaster, spaceship, missile, player transfers). Uses cursor-based read/write helpers for compact wire format. Compress/decompress variants add LZ4 compression with a 4-byte uncompressed-size prefix. Uses the workbuffer for intermediate storage during serialization and compression passes. Missile transfers always write/read 8 bytes for the smoke trail ID regardless of build (server writes 0, client writes actual value) to maintain consistent wire format across builds.

## Architecture Notes

The server broadcasts delta updates (compressed StatusChange batches and player inputs) each tick to connected clients, filtered to each client's 3x3 active grid region. Player inputs are echoed back from server to client alongside status changes to ensure physics determinism -- the client applies server-authoritative inputs rather than locally-generated ones. Broadcasting is a two-step process: `BufferFrame()` compresses and stores unfiltered data (including player inputs) into the ring buffer once per frame, then `SendUpdate()` is called per-client with data filtered by the game layer. Full state transfers use LZ4-compressed Frame serialization and are sent on initial connect or when a client's active region changes. Both server and client use the workbuffer for packet assembly and cursor-based binary read/write helpers for deserialization. Re-send support uses the server-side ring buffer of buffered frames; clients detect gaps via frame number tracking and piggyback re-send requests onto their input packets.
