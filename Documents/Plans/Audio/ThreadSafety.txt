Audio Thread Safety Fix
======================
Fix data race where XAudio2 callback thread calls ClearVoices() while
the main thread is reading/writing mStaticVoices in Update().

Findings Validation
-------------------

[C1] Data race on mStaticVoices - CONFIRMED
  ClearVoices() is called from OnCriticalError/OnReset/OnDestroyEngine on
  the XAudio2 callback thread. It directly modifies mStaticVoices (lines
  188-192) with no synchronization. The main thread iterates and modifies
  mStaticVoices throughout Update() (lines 404-515). This is a data race.

  Fix: Add an std::atomic<bool> flag (mbClearVoicesRequested). The XAudio2
  callback functions set the flag. Update() checks the flag at the top and
  performs the actual ClearVoices() work on the main thread.

[M2] ClearVoices leaks XAudio2 voices - REJECTED
  ClearVoices() intentionally nulls mpVoice before destruction. This is
  correct because ClearVoices is only called after the XAudio2 engine has
  reset or encountered a critical error, which internally destroys all
  source voices. Calling DestroyVoice() on already-destroyed voices would
  be a use-after-free. The comment on line 352 confirms: "After Reset() is
  called, all XAudio2SourceVoices are destroyed internally to AudioEngine
  and their pointers must be set to nullptr." The destructor pattern is
  different because it runs during normal shutdown when voices are still
  valid.

[L11] UpdateVolume null check on mpVoice - REJECTED
  With C1 fixed, ClearVoices work runs on the main thread only.
  UpdateVolume is also called from the main thread (via UpdateMusicStreams
  inside Update). There is no concurrent nulling of mpVoice, so the null
  check is unnecessary. Adding it would violate the "no error handling or
  validation" directive.

Order of Operations
-------------------
1. Add atomic flag to AudioManager.h
2. Modify ClearVoices() to only handle streaming voices (already mutex-protected)
   and set the flag for static voices
3. Modify callback functions to set flag instead of calling ClearVoices()
4. Add flag check at top of Update() to clear static voices on main thread

File: Engine/Source/Audio/AudioManager.cpp

2. Replace ClearVoices() (lines 186-212) with two parts:

   void AudioManager::ClearVoices()
   {
       // Static voices: no mutex protection, must run on main thread only
       for (auto& [rId, rStaticVoice] : mStaticVoices)
       {
           rStaticVoice.mpVoice = nullptr;
       }
       mStaticVoices.clear();

       // Streaming voices: protected by mutex, safe from any thread
       ClearStreamingVoices();
   }

   Add new private method ClearStreamingVoices() containing the streaming
   voice cleanup (current lines 194-211):

   void AudioManager::ClearStreamingVoices()
   {
       std::lock_guard<std::recursive_mutex> lock(mMusicStreamRecursiveMutex);

       if (mpCurrentMusicStream != nullptr)
       {
           mpCurrentMusicStream->mpVoice = nullptr;
       }
       mpCurrentMusicStream.reset();

       for (std::unique_ptr<StreamingVoice>& pPreviousStream : mPreviousStreams)
       {
           if (pPreviousStream != nullptr)
           {
               pPreviousStream->mpVoice = nullptr;
           }
       }
       mPreviousStreams.clear();
   }

3. Replace OnCriticalError, OnReset, OnDestroyEngine (lines 579-595) to
   set flag and only clear streaming voices immediately:

   void AudioManager::OnCriticalError()
   {
       Log("AudioManager::OnCriticalError()");
       mbClearVoicesRequested.store(true, std::memory_order_release);
       ClearStreamingVoices();
   }

   void AudioManager::OnReset()
   {
       Log("AudioManager::OnReset()");
       mbClearVoicesRequested.store(true, std::memory_order_release);
       ClearStreamingVoices();
   }

   void AudioManager::OnDestroyEngine() noexcept
   {
       Log("AudioManager::OnDestroyEngine()");
       mbClearVoicesRequested.store(true, std::memory_order_release);
       ClearStreamingVoices();
   }
