Network Code Cleanup: FindClient const_cast dedup + WriteGridCoord helper + SendPacket helper
=============================================================================================

Three small DRY cleanups combined into one plan.

=== Part A: FindClient const_cast dedup (Server.cpp) ===

Problem: Server.cpp has two identical FindClient overloads that differ only
in const qualification. The mutable version should delegate to the const
version via const_cast.

File: Engine/Source/Network/Server/Server.cpp

Change 1 -- Replace the mutable FindClient with a one-liner that delegates
to the const overload:

  BEFORE:
    ClientConnection* Server::FindClient(int64_t iClientId)
    {
        for (ClientConnection& rClient : mClients)
        {
            if (rClient.iClientId == iClientId)
            {
                return &rClient;
            }
        }
        return nullptr;
    }

  AFTER:
    ClientConnection* Server::FindClient(int64_t iClientId)
    {
        return const_cast<ClientConnection*>(std::as_const(*this).FindClient(iClientId));
    }

Leave the const overload unchanged.

=== Part B: WriteGridCoord helper ===

Problem: 8 manual two-line PushBack<int32_t>(coord.x)/PushBack<int32_t>(coord.y)
patterns across three files. ReadGridCoord exists in NetworkCursor.h but no write
counterpart.

--- Change 2 -- Add WriteGridCoord to NetworkCursor.h ---

File: Engine/Source/Network/NetworkCursor.h

Insert cursor-based WriteGridCoord after the existing ReadGridCoord,
and a Workbuffer overload below it:

  inline void WriteGridCoord(uint8_t*& pCursor, GridCoord coord)
  {
      WriteInt32(pCursor, coord.x);
      WriteInt32(pCursor, coord.y);
  }

  inline void WriteGridCoord(common::Workbuffer& rWorkbuffer, GridCoord coord)
  {
      rWorkbuffer.PushBack<int32_t>(coord.x);
      rWorkbuffer.PushBack<int32_t>(coord.y);
  }

=== Part C: SendPacket helper to reduce send-function boilerplate ===

Problem: 14 send functions across ClientSend.cpp (7) and ServerSend.cpp (7)
repeat the same tail pattern:
    std::span<const uint8_t> packetSpan = rWorkbuffer.Span<uint8_t>();
    ScopedSuppressAllocationTracking scopedSuppressAllocationTracking;
    // Heap: ENet allocates packet data internally
    ENetPacket* pPacket = enet_packet_create(packetSpan.data(), packetSpan.size(), flags);
    enet_peer_send(pPeer, channel, pPacket);

This 5-line block (with the scoped suppression, comment, and create+send)
is mechanically identical except for flags, channel, and peer.

Some functions additionally wrap the tail in a { } scope block for the
ScopedSuppressAllocationTracking lifetime -- the helper eliminates this need
since the suppression scope is contained within the helper.

--- Change 4 -- Add SendPacket helper to NetworkManager.h ---

File: Engine/Source/Network/NetworkManager.h

Add a static inline helper:

  static inline void SendPacket(ENetPeer* pPeer, uint8_t uiChannel,
      common::Workbuffer& rWorkbuffer, uint32_t uiFlags)
  {
      std::span<const uint8_t> packetSpan = rWorkbuffer.Span<uint8_t>();
      ScopedSuppressAllocationTracking scopedSuppressAllocationTracking;
      // Heap: ENet allocates packet data internally
      ENetPacket* pPacket = enet_packet_create(packetSpan.data(),
          packetSpan.size(), uiFlags);
      enet_peer_send(pPeer, uiChannel, pPacket);
  }

--- Change 5 -- Replace tail pattern in ClientSend.cpp (7 functions) ---

    NetworkManager::SendPacket(mpServerPeer, channel, rWorkbuffer, flags);

Remove the extra { } scope blocks that existed only to constrain
