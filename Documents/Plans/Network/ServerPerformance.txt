Server Performance: Buffer Pruning + Deferred Debug Serialization
==================================================================

Two validated performance fixes. Findings T3-2 (FindClient hash map) and T3-6
(bitfield intrinsics) were discarded after validation -- see Discarded section.

=== Part A: O(n^2) Buffer Pruning in BufferFrame ===

Problem: Server.cpp lines 212-223. std::erase_if over mPerCoordBufferedFrames
runs a lambda that linear-scans rGridUpdates for each entry. This is O(B * M)
where B = buffered coord count and M = active coord count.

Current scale: B and M are both small (~5-20 coords), so this isn't a
bottleneck today. However, the fix is trivial, eliminates an algorithmic wart,
and will matter if the grid grows.

File: Engine/Source/Network/Server/Server.cpp

Change 1 -- Build a local unordered_set before the erase_if:

  In BufferFrame(), replace lines 212-223:

  BEFORE:
    // Prune ring buffers for coords no longer in the active set
    std::erase_if(mPerCoordBufferedFrames, [&rGridUpdates](const auto& rEntry)
    {
        for (const auto& [coord, updateData] : rGridUpdates)
        {
            if (coord == rEntry.first)
            {
                return false;
            }
        }
        return true;
    });

  AFTER:
    // Prune ring buffers for coords no longer in the active set
    std::unordered_set<GridCoord> activeCoords;
    activeCoords.reserve(rGridUpdates.size());
    for (const auto& [coord, updateData] : rGridUpdates)
    {
        activeCoords.insert(coord);
    }
    std::erase_if(mPerCoordBufferedFrames, [&activeCoords](const auto& rEntry)
    {
        return !activeCoords.contains(rEntry.first);
    });


=== Part B: Deferred Debug Frame Serialization ===

Problem: Server.cpp lines 226-247. BufferFullFrame() is called every tick
(from ServerSession::BroadcastTick line 285) and serializes every active
coord's full Frame via std::ostringstream. Debug frame requests are rare
(only triggered by desync reports). This wastes CPU and memory every tick.

Fix: Instead of pre-serializing, store the raw Frame data and only serialize
when a debug frame request arrives. BufferFullFrame already receives Frame
pointers -- we need to copy the Frame data (not just pointers, since frames
are double-buffered and will be overwritten).

File: Engine/Source/Network/Server/Server.h

Change 2 -- Replace BufferedFullFrame serializedFrames with raw frame copies:

  BEFORE:
    struct BufferedFullFrame
    {
        int64_t iTick = 0;
        // Heap: serialized frame data per grid coordinate for debug frame requests
        std::unordered_map<GridCoord, std::string> serializedFrames;
    };

  AFTER:
    struct BufferedFullFrame
    {
        int64_t iTick = 0;
        // Heap: frame copies per grid coordinate for debug frame requests
        std::unordered_map<GridCoord, game::Frame> frameCopies;
    };

  Note: Forward declaration `struct Frame;` at top of Server.h must become
  `#include "Frame/Frame.h"` (or wherever Frame is defined) since we now store
  Frame by value. Check if Pch.h already provides this.

File: Engine/Source/Network/Server/Server.cpp

Change 3 -- Simplify BufferFullFrame to copy frames instead of serializing:

  BEFORE (lines 226-247):
    void Server::BufferFullFrame(int64_t iTick, const std::vector<std::pair<GridCoord, const game::Frame*>>& rFrames)
    {
        ScopedSuppressAllocationTracking scopedSuppressAllocationTracking;

        // Heap: ring buffer grows until steady state
        BufferedFullFrame buffered {};
        buffered.iTick = iTick;

        for (const auto& [coord, pFrame] : rFrames)
        {
            // Heap: stringstream allocates for frame serialization
            std::ostringstream frameStream(std::ios::binary);
            frameStream << *pFrame;
            buffered.serializedFrames.insert_or_assign(coord, frameStream.str());
        }

        mBufferedFullFrames.push_back(std::move(buffered));
        while (static_cast<int64_t>(mBufferedFullFrames.size()) > kiMaxBufferedFrames)
        {
            mBufferedFullFrames.pop_front();
        }
    }

  AFTER:
    void Server::BufferFullFrame(int64_t iTick, const std::vector<std::pair<GridCoord, const game::Frame*>>& rFrames)
    {
        ScopedSuppressAllocationTracking scopedSuppressAllocationTracking;

        // Heap: ring buffer grows until steady state
        BufferedFullFrame buffered {};
        buffered.iTick = iTick;

        for (const auto& [coord, pFrame] : rFrames)
        {
            // Heap: frame copy for deferred debug serialization
            buffered.frameCopies.insert_or_assign(coord, *pFrame);
        }

        mBufferedFullFrames.push_back(std::move(buffered));
        while (static_cast<int64_t>(mBufferedFullFrames.size()) > kiMaxBufferedFrames)
        {
            mBufferedFullFrames.pop_front();
        }
    }

File: Engine/Source/Network/Server/ServerReceive.cpp

  BEFORE (lines 121-128):

=== Discarded Findings ===

T3-2: FindClient hash map
  Discarded. Max 64 clients. Linear scan of a contiguous std::vector<ClientConnection>
  is cache-friendly and likely faster than hash map overhead at this scale. The existing
  NetworkCodeCleanup.txt const_cast dedup is still worthwhile as a DRY cleanup.

T3-6: Resend bitfield intrinsics (countr_zero)
  Discarded. The code already uses std::bit_width to limit scan range and early-exits
  when the bitfield is 0. The loop is capped at kiMaxResendFrames (8) resends over
  at most 64 bits. Switching to countr_zero would save a few iterations in the sparse
  case but adds complexity for negligible gain.
