# Visual Smoothing for Reconciliation State Corrections (Human Player Only)

## Problem

When async reconciliation (ClientReconciler) corrects the client's extrapolated
state, it swaps pCurrent with the replay workspace tip (ClientReconciler.cpp:314).
This instantly overwrites the human player's position, causing visible
teleporting/snapping on the next render frame.

## Solution

Maintain a per-coord "visual error offset" that captures the position delta at the
moment reconciliation overwrites pCurrent. The simulation snaps immediately (correct
for physics), but the render path adds a decaying offset for smooth visuals.

    visual_error = old_visual_position - new_simulation_position
    Each render frame: visual_error *= decay_factor
    rendered_position = simulation_position + visual_error

Scope: human player only, in the human's grid coord. No UUID matching needed --
we already know mHumanGridCoord and mHumanPlayerId.

## Constants

    kfVisualErrorDecayRate  = 15.0f   // per-second exponential decay (fast but smooth)
    kfVisualErrorMaxDistance = 5.0f   // discard offset above this (teleport is intentional)
    kfVisualErrorMinDistance = 0.001f // stop applying below this (avoid lingering micro-offsets)

Decay per render frame: decay = exp(-kfVisualErrorDecayRate * fDeltaTime)
At 60fps, ~78% retained per frame -> error halves in ~46ms -> visually gone in ~200ms.

## Architecture

The visual error lives on Game (game layer, not Frame -- Frame is pure).
It is captured after reconciliation applies and consumed during rendering.
Only one XMVECTOR needed (human player's coord). Multi-coord is irrelevant
because we only smooth the human player and they exist in one coord at a time.

    XMVECTOR vecPreSwapHumanPosition {};
    bool bHadPreSwapPosition = false;
    if (gpGame->HumanPlayerId().IsValid() && gpGame->mCoordFrames.contains(gpGame->mHumanGridCoord))
    {

        {

            bHadPreSwapPosition = true;
        }
    }

After the pCurrent swap loop and EnsureNextFrames() call (after line 326):

    // Compute visual error offset from position delta
    if (bHadPreSwapPosition && gpGame->HumanPlayerId().IsValid() && gpGame->mCoordFrames.contains(gpGame->mHumanGridCoord))
    {
        const Frame& rPostFrame = *gpGame->mCoordFrames.at(gpGame->mHumanGridCoord).pCurrent;
        if (auto oIdx = gpGame->HumanPlayerIndex(*rPostFrame.interpolate.pPlayers))
        {
            XMVECTOR vecPostPosition = rPostFrame.interpolate.pPlayers->pVecPositions[*oIdx];
            XMVECTOR vecError = XMVectorSubtract(vecPreSwapHumanPosition, vecPostPosition);
            // Add to existing error (don't replace -- previous error may still be decaying)
            XMVECTOR vecTotal = XMVectorAdd(gpGame->mVecVisualErrorOffset, vecError);
            float fDistance = XMVectorGetX(XMVector3Length(vecTotal));
            if (fDistance > kfVisualErrorMaxDistance)
            {
                gpGame->mVecVisualErrorOffset = {};
            }
            else
            {
                gpGame->mVecVisualErrorOffset = vecTotal;
            }
        }
    }

Note: kfVisualErrorMaxDistance needs to be accessible here. Either:
  (a) Declare it in Game.h as a static constexpr on Game, or
  (b) Duplicate the constant in ClientReconciler.cpp.
Option (a) is cleaner. Move the three constants to Game.h as:

    static inline constexpr float kfVisualErrorDecayRate = 15.0f;
    static inline constexpr float kfVisualErrorMaxDistance = 5.0f;
    static inline constexpr float kfVisualErrorMinDistance = 0.001f;

After line 300 (game::gpCamera->Update(...)):

    // Decay visual error offset for smooth reconciliation corrections
    {
        float fDisplayDeltaTime = 1.0f / static_cast<float>(gpGraphics->miMonitorRefreshRate);
        float fDecay = std::exp(-game::Game::kfVisualErrorDecayRate * fDisplayDeltaTime);
        game::gpGame->mVecVisualErrorOffset = XMVectorScale(game::gpGame->mVecVisualErrorOffset, fDecay);
        float fRemaining = XMVectorGetX(XMVector3Length(game::gpGame->mVecVisualErrorOffset));
        if (fRemaining < game::Game::kfVisualErrorMinDistance)
        {
            game::gpGame->mVecVisualErrorOffset = {};
        }
    }

## Flow Summary

1. ClientReconciler::ApplyResult() swaps pCurrent with replay result
   - BEFORE swap: capture human player position from old pCurrent
   - AFTER swap: compute delta, accumulate into mVecVisualErrorOffset
   - If delta > kfVisualErrorMaxDistance: discard (intentional teleport)

2. GameBase::Render() runs every render frame
   - Camera::Update() reads player position + visual error offset
   - Camera blends smoothly toward the offset target
   - After Camera::Update(), decay mVecVisualErrorOffset exponentially
   - Clear offset when magnitude < kfVisualErrorMinDistance

3. Net result: simulation is always correct (physics uses real position),
   camera smoothly absorbs the correction over ~200ms

## Notes

- Only the camera-facing position is smoothed. Entity rendering uses the true
  simulation position (correct -- other entities don't need smoothing since the
  human player is the only one whose correction is perceptible).
- The decay uses display-rate delta time (1/refreshRate), matching the camera's
  own blend timing for consistency.
- The offset accumulates additively (not replaced) so rapid consecutive
  reconciliations blend naturally without popping.
- CRC fast-path reconciliations (ClientReconciler.cpp:174) do NOT swap pCurrent,
  so they don't produce visual errors. Only bAnyFullReplay triggers the swap
  (line 302), which is the only case that needs smoothing.
