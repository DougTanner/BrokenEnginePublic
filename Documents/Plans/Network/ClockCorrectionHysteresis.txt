Clock Correction Hysteresis
===========================

Problem
-------
In ClientSessionBase::ComputeClockCorrectionNs() (ClientSessionBase.cpp line 225),
iTargetBehind is recalculated every tick from smoothed RTT:

    int64_t iTargetBehind = (iRttUs > 0) ? ((iRttUs / 2 + iTickTimeUs - 1) / iTickTimeUs + 1) : 1;

On WiFi or variable-latency connections, small RTT fluctuations cause this value to
oscillate by 1 frame each tick (e.g., alternating between 3 and 4). Since iError is
computed as (iOffset - iTargetBehind), the clock correction keeps nudging in alternating
directions, never converging. This creates jitter in the client's tick timing.

Fix
---
Add hysteresis: store the current target in a member (miCurrentTargetBehind) and only
update it when the freshly computed value differs by 2+ frames from the stored value.
On the first call (miCurrentTargetBehind == 0), accept the computed value immediately.

       {
