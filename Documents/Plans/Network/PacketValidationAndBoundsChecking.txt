Packet Validation and Bounds Checking
======================================

Problem
-------
Network packets are external input, not function parameters. Several receive
handlers read cursor data without checking that the packet is large enough,
which can cause out-of-bounds reads on malformed or truncated packets.
Additionally, LZ4 decompression sizes are read as int32_t without sign checks,
and the status change deserializer accepts out-of-range enum values.

Approach
--------
Per-handler minimum-size checks at the top of each handler (early return on
undersized packets). This is simpler and more KISS than refactoring
NetworkCursor into a bounds-checked cursor class. The packet size is already
available at all dispatch sites.

The general pattern: compute the fixed-size portion of the packet, check
iSize >= that value, and return early if not. For variable-length packets,
validate the variable portion after reading its length field.

        engine::PacketType eType = static_cast<engine::PacketType>(uiPacketType);

            uint8_t uiWireType = engine::ReadUint8(pCursor);
            int64_t iPlayerId = engine::ReadInt64(pCursor);

the size check.


Findings Not Addressed
----------------------
T1-1 (NetworkCursor bounds checking): Decided against refactoring NetworkCursor
to be bounds-checked. Per-handler size checks (this plan) are simpler, more
KISS, and sufficient. The cursor functions remain thin wrappers — all safety
comes from validating packet size before entering the read loop.
