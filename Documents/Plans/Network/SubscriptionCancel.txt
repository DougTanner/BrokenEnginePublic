Track Cancelled Subscriptions
=============================

Bug
---
In UnsubscribeStaleCoords (ClientSessionBase.cpp:114-116), when a kSubscribing
slot's coord is no longer desired, the slot is silently reset:

    if (rSlots.at(i).eState == CoordSubscriptionState::kSubscribing)
    {
        rSlots.at(i) = {};
    }

The server never learns the subscription was cancelled. It completes the
handshake (ServerSubscribeAccept + full state ~KB compressed), the client
processes it into kActive, then the next UnsubscribeStaleCoords call triggers a
full unsubscribe round-trip. Wasted bandwidth and latency.

Fix Overview
------------
Store cancelled coords in a small vector on Client. When ServerSubscribeAccept
or ServerCoordFullState arrives for a cancelled coord, immediately SendUnsubscribe
for the server-assigned slot (or reject the full state), avoiding the full state
transfer entirely.

Change 4: ClientReceive.cpp - Intercept ServerCoordFullState for cancelled coords
================================================================================

File: Engine/Source/Network/Client/ClientReceive.cpp
Lines 70-90, the slot validation block. Add cancel check after the existing
validation but before pushing the full state. Insert after line 90 (the final

BEFORE (line 92):
    ReceivedCoordFullState fullState {};

AFTER:
    // If this coord was cancelled while kSubscribing, reject the full state
    auto& rCancelled = mCancelledSubscriptions;
    auto cancelIt = std::ranges::find(rCancelled, coord);
    if (cancelIt != rCancelled.end())
    {
        rCancelled.erase(cancelIt);
        Log(kLogNetwork, "Client::ServerCoordFullState Cancelled Coord: ({},{}) Slot: {}", coord.x, coord.y, uiSlotIndex);
        rSlot = {};
        return;
    }

    ReceivedCoordFullState fullState {};

Note: In the full-state-before-accept race case, the slot was just set up by
lines 74-78 (kUnsubscribed path). Resetting it here is correct -- the accept
will arrive later and find kUnsubscribed, at which point the accept intercept
(Change 3) handles it. However, if the cancel entry was already consumed by
this path, the accept path needs no cancel entry. The coord appears in
mCancelledSubscriptions once per cancellation, and either ServerSubscribeAccept
or ServerCoordFullState consumes it (whichever arrives first). The second
arrival finds a kUnsubscribing or kUnsubscribed slot and returns early via
existing validation.
