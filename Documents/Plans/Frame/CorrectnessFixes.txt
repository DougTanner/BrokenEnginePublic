B2. AreaLightsPostRender::AllocateAndCopy missing puiIds copy
-------------------------------------------------------------

File: Engine/Source/Frame/Collections/AreaLights/AreaLights.cpp (lines 30-33)
File: Engine/Source/Frame/Collections/AreaLights/AreaLightsUpdate.cpp (lines 26-39)

Issue: Every other indexable PostRender collection (PointLights, HexShields, Sounds, Pushers) copies
puiIds in AllocateAndCopy via memcpy and has an empty Update(). AreaLightsPostRender does the copy
in Update() with a per-element loop instead. This is inconsistent and slower.

Fix 1 of 2 - Add memcpy to AllocateAndCopy:

  File: Engine/Source/Frame/Collections/AreaLights/AreaLights.cpp
  Old (lines 30-33):
    void AreaLightsPostRender::AllocateAndCopy(AreaLightsPostRender& rCurrent, const AreaLightsPostRender& rPrevious)
    {
    	Allocate(rCurrent, rPrevious, rCurrent.Members());
    }

  New:
    void AreaLightsPostRender::AllocateAndCopy(AreaLightsPostRender& rCurrent, const AreaLightsPostRender& rPrevious)
    {
    	Allocate(rCurrent, rPrevious, rCurrent.Members());

    	if (rCurrent.iCount > 0)
    	{
    		std::memcpy(rCurrent.puiIds, rPrevious.puiIds, rCurrent.iCount * sizeof(rCurrent.puiIds[0]));
    	}
    }

Fix 2 of 2 - Make Update() empty:

  File: Engine/Source/Frame/Collections/AreaLights/AreaLightsUpdate.cpp
  Old (lines 26-39):
    void AreaLightsPostRender::Update([[maybe_unused]] game::Frame& __restrict rFrame, [[maybe_unused]] const game::Frame& __restrict rPreviousFrame)
    {
    	AreaLightsPostRender& __restrict rCurrent = rFrame.postRender.areaLights;
    	const AreaLightsPostRender& __restrict rPrevious = rPreviousFrame.postRender.areaLights;

    	for (int64_t i = 0; i < rCurrent.iCount; ++i)
    	{
    		// Load
    		area_lights_t id = rPrevious.puiIds[i];

    		// Save
    		rCurrent.puiIds[i] = id;
    	}
    }

  New:
    void AreaLightsPostRender::Update([[maybe_unused]] game::Frame& __restrict rFrame, [[maybe_unused]] const game::Frame& __restrict rPreviousFrame)
    {
    }

R1. No death spiral prevention in Release builds
-------------------------------------------------

File: Engine/Source/Frame/TimeStep.cpp (lines 40-63)

Issue: The accumulator clamping (lines 46-58) is inside the `if constexpr (kbEnableDebugInput)` block.
In Release builds where kbEnableDebugInput is false, the else branch (lines 60-63) accumulates time
without any clamp. A frame stall (e.g., shader compilation, alt-tab) causes unbounded iTicks, freezing
the game in a physics catch-up loop.

The DecreaseTimeScale() call must stay debug-only (it references debug text), but the accumulator clamp
is safe for all builds. The constants kiMaxAccumulatorTicks (4) and game::kTickNs are always available.

Fix:

  File: Engine/Source/Frame/TimeStep.cpp
  Old (lines 60-63):
    	else
    	{
    		mTickRemainderNs += (realDeltaNs * miTimeMultiply) / miTimeDivide;
    	}

  New:
    	else
    	{
    		mTickRemainderNs += (realDeltaNs * miTimeMultiply) / miTimeDivide;

    		// Death spiral prevention: clamp accumulator to prevent backlog cascade
    		std::chrono::nanoseconds maxAccumulator = game::kTickNs * kiMaxAccumulatorTicks;
    		if (mTickRemainderNs > maxAccumulator)
    		{
    			mTickRemainderNs = maxAccumulator;
    		}
    	}


R2. Unclamped terrain avoidance interpolation parameter
-------------------------------------------------------

File: Projects/BrokenEngineSandbox/Source/Frame/TerrainUtils.cpp (line 163)

Issue: fPercent is computed as (elevation - min) / max. On steep terrain where elevation exceeds
kfAvoidTerrainMin + kfAvoidTerrainMax (0.5 + 2.5 = 3.0), fPercent exceeds 1.0, causing the lerp
on line 165 to extrapolate fAvoidDeltaAngle beyond kfAvoidTerrainDeltaAngleMax. This produces
over-aggressive avoidance steering.

Fix:

  File: Projects/BrokenEngineSandbox/Source/Frame/TerrainUtils.cpp
  Old (line 163):
    		float fPercent = fLeftElevation > fRightElevation ? (fLeftElevation - kfAvoidTerrainMin) / kfAvoidTerrainMax : (fRightElevation - kfAvoidTerrainMin) / kfAvoidTerrainMax;

  New:
    		float fPercent = fLeftElevation > fRightElevation ? (fLeftElevation - kfAvoidTerrainMin) / kfAvoidTerrainMax : (fRightElevation - kfAvoidTerrainMin) / kfAvoidTerrainMax;
    		fPercent = std::clamp(fPercent, 0.0f, 1.0f);


R4. smPriorityIslands never cleared between constructions
----------------------------------------------------------

File: Engine/Source/Frame/IslandTerrain.cpp (line 40)

Issue: smPriorityIslands is a static inline std::vector (declared in IslandTerrain.h:27). The
constructor pushes island CRCs into it (line 40) but never clears it first. If IslandTerrain is
constructed more than once (e.g., returning to menu and starting a new game), the vector accumulates
duplicate CRCs. This causes duplicate chunk load requests and incorrect sort order.

Fix:

  File: Engine/Source/Frame/IslandTerrain.cpp
  Old (lines 28-29):
    IslandTerrain::IslandTerrain()
    {
    	gpIslandTerrain = this;

  New:
    IslandTerrain::IslandTerrain()
    {
    	gpIslandTerrain = this;
    	smPriorityIslands.clear();
