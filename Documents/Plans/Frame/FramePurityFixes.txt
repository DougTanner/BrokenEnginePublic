Frame Purity Fixes Plan
=======================

Remove global singleton access from Frame update/lifecycle code (P1-P4 from audit).


================================================================================
P1. Remove gpAudioManager from Frame update code (7 call sites)
================================================================================

Currently, 7 call sites in Frame PostCollision/Explode code call
gpAudioManager->PlayOneShot3d / PlayOneShot directly. These are all
#ifdef BT_CLIENT and all occur during PostCollision or Explode, which runs
during reconciliation replays. The AudioManager already checks kRecalculated
internally and returns early, but accessing the global at all violates Frame
purity.

APPROACH: Add a deferred audio event buffer to FramePostRenderBase. Frame code
writes events into this buffer. After the tick completes (outside Frame code),
the caller drains the buffer and plays the sounds. The buffer is only drained
when not recalculating, preserving the existing behavior.

--- Step 1: Add DeferredAudioEvent struct and buffer to FramePostRenderBase ---

File: Engine/Source/Frame/FrameBase.h

Add before the FramePostRenderBase class definition:

  #if defined(BT_CLIENT)
  struct DeferredAudioEvent
  {
      common::crc_t audioCrc;
      XMVECTOR vecPosition;
      float fVolume;
      float fPitch;
      float fPitchRange;
      bool b3d;
  };

  inline constexpr int64_t kiMaxDeferredAudioEvents = 64;
  #endif // BT_CLIENT

Add to FramePostRenderBase as a public member:

  #if defined(BT_CLIENT)
  int64_t iDeferredAudioEventCount = 0;
  DeferredAudioEvent deferredAudioEvents[kiMaxDeferredAudioEvents] {};
  #endif // BT_CLIENT

--- Step 2: Add helper to write deferred audio events ---

File: Engine/Source/Frame/FrameBase.h

Add two free functions (or static methods) next to the struct:

--- Step 3: Add drain function ---

File: Engine/Source/Frame/FrameBase.h (or FrameBase.cpp if preferred)

  #if defined(BT_CLIENT)
  inline void DrainDeferredAudioEvents(FramePostRenderBase& rPostRender, const FrameInterpolateBase& rInterpolate)
  {
      if (rInterpolate.frameFlags & FrameFlags::kRecalculated)
      {
          rPostRender.iDeferredAudioEventCount = 0;
          return;
      }

      for (int64_t i = 0; i < rPostRender.iDeferredAudioEventCount; ++i)
      {
          const DeferredAudioEvent& rEvent = rPostRender.deferredAudioEvents[i];
          if (rEvent.b3d)
          {
              gpAudioManager->PlayOneShot3d(/* need Frame ref - see note */)
          }
          else
          {
              gpAudioManager->PlayOneShot(...)
          }
      }
      rPostRender.iDeferredAudioEventCount = 0;
  }
  #endif // BT_CLIENT

NOTE: PlayOneShot/PlayOneShot3d currently take `const game::Frame&` for the
kPostRender/kRecalculated asserts. Since we've already checked kRecalculated
before draining, we need either:
  (a) Add new AudioManager methods that don't take Frame (PlayOneShotDirect), or
  (b) Pass the Frame to DrainDeferredAudioEvents and forward it.

Option (b) is simpler. The drain function lives in GameBase.cpp or Game.cpp
(outside Frame code), not in FrameBase.h. This keeps the AudioManager include
out of Frame headers.

REVISED: Put DrainDeferredAudioEvents in GameBase.cpp (or Game.cpp):

          }
      }
      rPostRender.iDeferredAudioEventCount = 0;
  }
