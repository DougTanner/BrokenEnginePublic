PlayersInterpolate: Move pfRotationAccelerationXs/Ys from SharedMembers() to ClientMembers()
=========================================================================================

AUDIT CORRECTION: The audit proposed moving pfAnimationTimes as well, but validation
shows pfAnimationTimes CANNOT be moved. It is read and written outside #if defined(BT_CLIENT)
in Update (copy-forward at line 132), Transfer (line 247), and Spawn (line 585). The server
uses it to preserve animation time across cross-cell transfers. It must remain in SharedMembers().

Only pfRotationAccelerationXs and pfRotationAccelerationYs can be moved. They are:
- Written only inside #if defined(BT_CLIENT) in Update (lines 138-139)
- Read only in PlayersRender.cpp (lines 112-113), which is entirely #ifdef BT_CLIENT
- Initialized to 0.0f in Spawn (lines 586-587), which must be gated with #ifdef BT_CLIENT
- Already excluded from ServerCrcMembers()
- Zero-initialized by ServerCollectionRead via memset, so client receives correct defaults

Impact: Server no longer allocates or serializes these two float arrays per player.
No behavioral change on either client or server.

Files changed:
  1. Players.h  (move field declarations, update SharedMembers/ClientMembers)
  2. Players.cpp (gate Spawn initialization with #ifdef BT_CLIENT)

No other files need changes. PlayersUpdate.cpp and PlayersRender.cpp already have
all reads/writes inside #if defined(BT_CLIENT).
