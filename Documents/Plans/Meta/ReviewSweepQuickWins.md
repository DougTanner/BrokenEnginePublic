# Review-Sweep Quick Wins Batch

## Summary

**What this plan does:** Applies a batch of 13 small, independent, mostly-mechanical fixes surfaced by the 9c0b44d8..672b292e post-implementation review, spread across Ui debug tools, the Graphics render/uniform/pipeline layer, the Input raw-input path, one game collection, the DataPacker asset preprocessor, and the two Sandbox vcxprojs. Nothing touches determinism/CRC, `kiVersion`/`.pack` layout, replays, or the wire — the only runtime-behavior changes are a debug-widget hit-target tweak, a dead-uniform removal (compile-checked both language sides), an allocation-tracking suppression on a recoverable input-failure path, and an RAII fix to a debug render tripwire.

**Why it's good for the codebase:** Closes several concrete robustness holes (an `std::out_of_range` throw on a hostile disk folder name in `BakeRoute`; a silently-zero-padded truncated cached chunk in `ExportJob`; a permanently-wedged render tripwire on any exception in `SpaceshipsRender`; non-ASCII asset paths failing for EXR imports), removes genuinely dead machinery (the `fTerrainEarlyOut` uniform field + wrapper + upload, six phantom include dirs), fixes a real allocation-tracker false-break on a recoverable input path, adds a missing indirect-slot bounds ASSERT that its two siblings already carry, and deletes redundant pipeline `Destroy()`s and duplicated log-and-rethrow blocks. Each is too small for its own plan but real.

## Execution steps

Each item is independent; apply in any order. Citations are current.

1. **TweakSectionFlags mask off-by-one.** `Engine\Source\Ui\Screens\TweaksScreen\TweaksScreenBase.h:43` — `static_assert(static_cast<int>(TweakSection::kCount) <= 32, ...)` permits exactly 32, but `kAllSectionFlags` at `:52` computes `(1u << kCount) - 1u`, UB at that bound. Tighten the assert to `< 32` (or make the mask overflow-safe). Latent only — `kCount` is 12.

2. **CurveWidget grab radius + add-then-drag.** `Engine\Source\Ui\CurveWidget.cpp` — `DragPoint` (`:90`) uses `kfPointRadius = 5.0f` (`:12`) as the grab half-size, so a left-click 10–24 px from a control point falls through to `AddPoint` (`:106-115`, add at `:111`) instead of grabbing; a freshly added point also only sets `bInteracting` and doesn't hand off to drag. Pass a larger grab radius to `DragPoint` and/or pre-check proximity via `GetPlotMousePos` before `AddPoint`; restore add-then-drag. Debug-tool UX only; do **not** reintroduce the old hand-rolled editor.

3. **Remove dead `fTerrainEarlyOut` uniform.** No shader reads the field (verified across `Engine\Data\Shaders\**`; the only hit is a comment in `Terrain.frag` — contrast `fWaterEarlyOut`, which is still read). Delete: the `GlobalLayout` field (`Engine\Data\Shaders\ShaderLayoutsBase.h:380`), the upload (`Engine\Source\Graphics\Render\GlobalUniforms.cpp:394` `rGlobalLayout.fTerrainEarlyOut = gTerrainEarlyOut.Get();`), and the `gTerrainEarlyOut` wrapper — **both** the extern declaration (`Engine\Source\Ui\WrapperBase.h:233`) and the definition (`Engine\Source\Ui\WrapperBase.cpp:14`). Verified: no other consumer references the wrapper (no TweaksScreen/SliderMap registration), so those four sites are the complete set. Compile-checked on both language sides. Shader repack.

4. **Guard `std::stoll` on a disk-derived folder name.** `DataPacker\Source\ExportJobs\Island\BakeRoute.cpp:190` — `RemoveOrphanedLeafFolders` calls `std::stoll(name)` on an all-digit `directory_iterator` filename with no length cap; ≥19 digits throws `std::out_of_range`. Disk contents are a trust boundary — length-cap the digit test or catch-and-skip.

5. **Delete six phantom `..\..\..\Data` include dirs.** `$(ProjectDir)\..\..\..\Data` resolves to nonexistent `Projects\Data`. Remove that one token from each `AdditionalIncludeDirectories` line — the correct `$(ProjectDir)\..\..\Data` (`Projects\BrokenEngineSandbox\Data`, which exists) is present on every one of these lines, keep it:
   - `Projects\BrokenEngineSandbox\Platforms\VisualStudio2026\BrokenEngineSandbox.vcxproj:109, 166, 236`
   - `Projects\BrokenEngineSandbox\Platforms\VisualStudio2026\BrokenEngineSandboxServer.vcxproj:107, 164, 234`

6. **Suppress heap alloc on recoverable input-failure log.** `Engine\Source\Input\RawInputManager.cpp:54` and `:76` — `UpdateFocus` failure logs call `common::LastErrorString().data()`; `LastErrorString()` returns `std::string` by value (always exceeds SSO → heap alloc) on a recoverable path in the tracked main loop. Wrap each with `ScopedSuppressAllocationTracking` + a `// Heap:` comment. (A third call at `:214` in `HandleRawInput` is a separate `DEBUG_BREAK` path — see Additional candidate locations, not folded here.)

7. **RAII the render tripwire + promote to matching collections.** `Projects\BrokenEngineSandbox\Source\Frame\Collections\Spaceships\SpaceshipsRender.cpp:76` `ASSERT(!sbRenderActive.exchange(true))` has no unwind protection before the trailing `sbRenderActive.store(false)` at `:189`; a throw between them (e.g. the capacity ASSERT, buffer-manager allocs, or `EvaluateAnimation`) wedges it true and every later `Render` false-asserts. Make it an RAII guard (set on construct, reset on destruct). **Resolved (grill): promote the tripwire to the other slab-cursor render collections.** First enumerate the exact matching set — every `Projects\BrokenEngineSandbox\Source\Frame\Collections\**\*Render.cpp` that renders into a shared slab buffer indexed by a running cursor (Spaceships' `siRendered`) guarded by an `iBufferCapacity` ASSERT — and **report that set** before editing. Add the same RAII tripwire to each matching collection; do **not** add atomics to render collections that don't match the pattern. (`sbRenderActive` is Spaceships-only today, so the set must be derived from the pattern, not assumed.)

8. **UTF-8 asset path boundaries** (split by library after verification):
   - **(a) EXR — apply.** `DataPacker\Source\ExportJobs\Texture\Texture.cpp:142` — `exr_start_read(..., rPath.string().c_str(), ...)`: change to `reinterpret_cast<const char*>(rPath.u8string().c_str())`. Verified correct: OpenEXR's win32 impl unconditionally does `MultiByteToWideChar(CP_UTF8, ...)` → `CreateFileW`, so the current ANSI `.string()` bytes are the actual bug; ASCII paths are unaffected.
   - **(b) gli/KTX — gli memory-overload (resolved, grill).** Two gli sites: `DataPacker\Source\ExportJobs\ExportTexture.cpp:89` `gli::load(mInputPath.string())` and `DataPacker\Source\ExportJobs\ExportCubemapIbl.cpp:20` `gli::load(rPath.string())` (folded sibling — same fix). A plain `u8string()` swap is **broken for gli** (ANSI `fopen_s`, no UTF-8 conversion; would regress ACP-representable non-ASCII paths → `gli::load` empty → the `ASSERT(!texture.empty())` next line fires). Instead: read the file bytes from the `std::filesystem::path` (a `std::ifstream(path, std::ios::binary)` — the `path` overload opens the wide path correctly on Windows; or reuse `common::ReadEntireFile` if it is `path`-based and wide-correct) and feed them to gli's memory overload `gli::load(const char* data, std::size_t size)`. Add one small shared DataPacker helper (e.g. `LoadGliFromPath(const std::filesystem::path&)`) consumed by both sites. Byte-identical KTX load for valid inputs; fixes non-ASCII paths with no ANSI regression.

10. **Fix the `miIndirectSlotCount` comment.** `Engine\Source\Graphics\Objects\Pipeline.h:164` — comment claims "= max(framebufferCount, 3)", but the `kIndirectDeviceLocal` compute branch (`PipelineCreator.cpp:711`) sets 1, and `SetupIndirectBuffer` (`PipelineCreator.cpp:97`) stamps it unconditionally even for no-indirect pipelines. Correct the comment to match actual behavior.

11. **Add the missing indirect-slot bounds ASSERT.** `Engine\Source\Graphics\Objects\Pipeline.cpp:290` `RecordDrawIndirectSet2` inlines the offset (`:304`) without the `ASSERT(iIndirectSlot < miIndirectSlotCount)` that siblings `RecordDrawIndirect` (`:285`) and `RecordComputeIndirect` (`:342`) carry. Mirror `RecordDrawIndirect:281` — materialize `int64_t iIndirectSlot = mInfo.flags & kIndirectDeviceLocal ? 0 : iCommandBuffer;`, assert `iIndirectSlot < miIndirectSlotCount`, then compute the offset from it.

12. **Delete three redundant pre-`Create` `Destroy()`s.** `Engine\Source\Graphics\Managers\PipelineManager.cpp:201` (`mSpreadPipelines[iPass].Destroy();`), `:234` (`mCombinePipeline.Destroy();`), `:256` (`mLightingTemporalPipeline.Destroy();`) — `Pipeline::Create` self-destroys first (`Pipeline.cpp:87`) and these `Create*` members are ctor-only. Delete the three `.Destroy()` lines.

13. **Fold duplicated log-and-rethrow into `CreateModelPipeline`.** `Engine\Source\Graphics\Managers\DynamicPipelines.cpp` has two verbatim `try { CreateModelPipeline(...) } catch (const common::CorruptStreamException&) { LOG; throw; }` blocks (`:65-90` in `CreateModelPipeline(crc,...)`, `:115-143` in `CreateModelPipelineShadow(...)`). The core overload `CreateModelPipeline(const ModelPipelineSpec&)` at `:37-46` does not log-and-rethrow — move the log-and-rethrow into it (it has the scene CRC and name) and drop the two duplicated wrappers.

14. **Post-read stream check on the cached-chunk fast path.** `DataPacker\Source\ExportJobs\ExportJob.cpp:138-148` — `RunExport`'s `!mbDirty` path sizes from `file_size`, `fileStream.read(...)` at `:146`, and returns with no `good()`/`gcount()` check; `CheckDirty` validates only the 16-byte header, so a chunk truncated after its header silently packs a zero tail (`resize` zero-inits). Add `VERIFY_SUCCESS(fileStream.good())` (or a `gcount` check) and fall back to dirty re-export on failure.

15. **(Optional) Guard `VkNameImpl`'s prefix strip.** `Engine\Source\Graphics\GraphicsUtils.cpp:50` — for an unrecognized `VkObjectType`, `string_VkObjectType` returns "Unhandled VkObjectType" and the fixed +15-byte prefix strip yields an in-bounds garbage tail (`kbVulkanDebugLayers`-only, harmless). Guard on the expected `"VK_OBJECT_TYPE_"` prefix or leave a comment. Lowest value; drop if time-boxed.
