# Architecture: GameBase Dead Virtuals & Server MenuInput Plumbing

## Summary
**What this plan does:** Removes dead abstraction from the engine↔game seam across `Engine/Source/GameBase.{h,cpp}`, `Engine/Source/Main.cpp`, and the game's `Save/GameSaveLoad.{h,cpp}` + `Game.{h,cpp}`. It (1) deletes the never-called pure virtual `GameBase::ReplayFile()` (plus its `game::Game` override), (2) moves `GameBase::Reset()` and `GameBase::QuicksaveFile()` off the engine interface down to `game::Game` (making `QuicksaveFile()` public there), (3) deletes the structurally-dead server-side MenuInput→`Quickload`/`Quicksave` input path (dropping the now-dead `MenuInput` parameter from the `BT_SERVER`-only `GameBase::ServerUpdate`), and (4) tightens the client/server guard scope on three more client-only `GameBase` seam members (`ShouldTrapCursor`, `ProcessMenuInput`, `ProcessInput`) so the server build no longer carries them. No engine- or player-visible behavior changes; the networked `kClientSaveRequest`/`kClientLoadRequest`/`kClientResetRequest` path — the real server save/load/reset trigger — is untouched.

**Why it's good for the codebase:** Deletes three virtuals that widen the engine's interface without any engine consumer (dead-abstraction debt on the exact seam the root `AGENTS.md` polices), removes a structurally-dead code path that *fakes* a working server quicksave/quickload trigger the headless build can never reach (misleading dead code implying a feature that does not exist), and narrows three more seam members to the client build they actually serve (matching the repo's "guard client-only code at the narrowest scope" rule and the already-guarded sibling virtuals `ShouldUseCrosshair`/`ShouldShowInGameUi`). Fully compile-checked, no wire/CRC/save-format exposure. Also reconciles the recorded conflict with `Network/ServerPauseAndResetSemantics.md` by taking sole ownership of the MenuInput/`Quickload` deletion.
