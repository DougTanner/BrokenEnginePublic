# Linter Tooling for C++ Style Guide

## Status (2026-03-15)
Reference document only. No .clang-format or .clang-tidy has been set up.
.editorconfig EXISTS at repo root with comprehensive VS C++ formatting settings (Allman braces, spacing, indentation).
The EditorConfig already covers much of what .clang-format would provide for Visual Studio users.
Style guide rules are current through #59; rules 58 (#if defined) and 59 (case indentation) were added after this analysis and are not covered below.

## Summary
Analysis of which C++ style guide rules can be enforced by deterministic tools (clang-format, clang-tidy, EditorConfig) vs which require AI review.

## Clang-Format (.clang-format)
Handles formatting rules with zero ongoing effort. VS applies on save or Ctrl+K, Ctrl+D.

| Rule | Style Guide # | Clang-Format Setting |
|------|--------------|---------------------|
| Tabs for indentation | 1 | `UseTab: Always`, `IndentWidth: 4` |
| Allman brace style | 2 | `BreakBeforeBraces: Allman` |
| No space in `>>` | 30 | Default behavior |
| Keep params on one line | 51 | `BinPackParameters: true`, `AllowAllParametersOfDeclarationOnNextLine: false` |
| Space before `{}` init | 52 | `SpaceBeforeCpp11BracedList: true` |
| Include sort order | 47 | `SortIncludes`, `IncludeCategories` |

## Clang-Tidy (.clang-tidy)
Handles code pattern checks. Runs during build or on-demand via VS Code Analysis.

| Rule | Style Guide # | Clang-Tidy Check |
|------|--------------|------------------|
| C++ casts not C casts | 11 | `cppcoreguidelines-pro-type-cstyle-cast` |
| `nullptr` not `NULL` | 28 | `modernize-use-nullptr` |
| `override` keyword | 29 | `modernize-use-override` |
| `using` not `typedef` | 23 | `modernize-use-using` |
| Naming conventions (partial) | 3, 7 | `readability-identifier-naming` |
| `const` correctness | 18 | `misc-const-correctness` |
| Float literal suffix | 27 | `readability-uppercase-literal-suffix` |

## EditorConfig (.editorconfig)
Handles basic editor settings: tab vs spaces, tab width, trailing whitespace, final newline.

## NOT Automatable (Requires AI Review)

| Rule | # | Why |
|------|---|-----|
| Hungarian notation (full scheme) | 3 | Requires understanding variable semantics |
| `auto` restrictions (specific exceptions) | 15 | Tools can't distinguish allowed vs disallowed cases |
| `std::vector::at()` not `[]` | 16 | Would need custom clang-tidy check |
| No `std::array`/`std::span`/`std::bitset` | 21 | Custom check needed |
| `Count` not `Num` | 14 | Semantic naming preference |
| `.reserve()` before multiple `.push_back()` | 53 | Requires data-flow analysis |
| No abbreviations in names | 56 | Requires understanding intent |
| No `Impl`/`Internal` suffixes | 57 | Simple grep could work but edge cases |
| Exceptions for fatal errors only | 9 | Semantic judgment |
| `if constexpr` feature flags | 6 | Architectural pattern |
| Workbuffer over local vectors | CLAUDE.md | Project-specific architectural rule |
| `int64_t` default integer | 13 | Context-dependent |
| `unordered_map` not `map` | 32 | Custom check feasible |

## Recommendation
1. `.clang-format` — eliminates ~30-40% of style findings with zero ongoing effort
2. `.clang-tidy` — catches modernization and cast issues
3. Keep AI review for Hungarian notation, `auto` restrictions, architectural patterns, and semantic naming
