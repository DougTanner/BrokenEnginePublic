Replace OpenEXR with tinyexr
============================

Context
-------
OpenEXR is used in the DataPacker for HDR image loading (texture export pipeline). It is heavyweight -- pulls in Imath, zlib, libdeflate, and has a complex build system. tinyexr (BSD-3) is a single-header library that handles common EXR read/write for single-part files.

Why
---
- Dramatically simpler build: one header vs multi-library dependency chain
- Reduces ThirdParty complexity and build time
- BSD-3 license is permissive for commercial use
- DataPacker likely only reads single-part EXR files for HDR environment maps

Precondition
------------
Verify that the DataPacker's EXR usage is limited to single-part read-only. If deep images or multi-part files are used, tinyexr cannot replace OpenEXR.

Changes
-------

1. ThirdParty/
   - Add tinyexr header (single file, or git submodule)
   - Remove openexr submodule (after migration complete)

2. DataPacker vcxproj
   - Remove OpenEXR include paths and library references
   - Add tinyexr include path

3. DataPacker/Source/ (ExportTexture or wherever EXR is loaded)
   - Replace OpenEXR API calls with tinyexr equivalents
   - Key mapping:
     - Imf::InputFile / Imf::RgbaInputFile -> LoadEXR() or LoadEXRFromMemory()
     - Channel access -> float* RGBA output array
     - Width/height from EXRHeader struct

Notes
-----
- Verify HDR cubemap output is visually identical after migration
- tinyexr supports EXR 1.x and 2.x single-part, ZIP/ZIPS/PIZ/RLE compression
