Visual Quality Improvements Plan
=================================

Validation
----------

Finding 1.1 [Technique Limitation] -- Single-pass shadow blur
STATUS: VALID
  PipelineManager.cpp:237-248 creates a single compute pipeline "ShadowBlur" reading
  mShadowTexture and writing mShadowBlurTexture. The shader (ShadowBlur.comp) applies an 11x11
  2D Gaussian kernel in a single pass, sliding a pixel window row-by-row. This is O(N^2) per
  texel rather than the O(2N) of a separable two-pass approach. Performance scales poorly if
  the kernel size ever increases.

Finding 2.1 [Quality Gap] -- Default 2x MSAA is minimal
STATUS: VALID
  WrapperBase.cpp:9 defines gSampleCount with default VK_SAMPLE_COUNT_2_BIT. The allowed values
  list already includes 4x through 64x. Changing the default to 4x is trivial (one constant).
  4x is a reasonable default for modern GPUs -- the performance cost is modest and the quality
  improvement over 2x is significant (especially for geometric edges).

Finding 3.1 [Quality Gap] -- Swapchain uses UNORM instead of SRGB
STATUS: INVALID -- Reject this change
  InstanceManager.cpp:512-520 selects B8G8R8A8_UNORM for the swapchain. The finding claims manual
  gamma correction is required in every final-output shader via fPbrGamma. After reading all
  shaders that write to the swapchain (Model.frag, Terrain.frag, Water, Particles, etc.), NONE of
  them apply gamma correction to their final output. The fPbrGamma uniform is ONLY used inside
  TonemapIBL() for IBL cubemap sample processing within Model.frag, and those results are
  immediately converted back to linear via SRGBtoLinear(). The unused Tonemap() function at
  Model.frag:116 also references gamma but is never called.

  This means the engine currently outputs linear color directly to the display via UNORM, which
  results in an overall darker/more saturated look. Switching to SRGB format would change the
  appearance of EVERYTHING rendered -- terrain, models, particles, water, smoke, lighting, UI.
  Every artistic parameter in the engine has been tuned against the current UNORM output. This is
  not a bug fix; it is a fundamental change to the entire visual pipeline that would require
  re-tuning all lighting, exposure, color, and material parameters across the entire engine.
  REJECT.

Finding 4.1 [Quality Gap] -- Transparent materials cast full shadows
STATUS: VALID but LOW PRIORITY
  DynamicPipelines.cpp:90-100 creates shadow pipelines using ModelShadow.frag, which outputs a
  constant 0.0f regardless of material alpha. The shadow pipeline does bind model descriptors
  (bAddModelDescriptors = true at line 109), so material data IS accessible. However, implementing
  alpha-aware shadows requires: (1) sampling the color texture in the shadow pass, (2) discarding
  fragments based on alpha, and (3) potentially modulating shadow intensity for semi-transparent
  materials. This is a real quality gap but low priority unless the game has prominent transparent
  objects casting shadows.

Finding 5.1 [Quality Gap] -- No explicit CFL stability check
STATUS: INVALID -- Reject this change
  WindUniforms.cpp:68 computes fWindTimeScale = fDeltaTime * 60.0f * gWindTimeScale.Get().
  The wind simulation (WindSpread.frag) already has multiple stability safeguards:
  - Advection displacement is clamped to 3 texels max (line 59-64: fMaxStep = fTexelSize * 3.0f)
  - Diffusion blend factor is clamped to 1.0 (line 96: min(1.0f, ...))
  - Output magnitude is soft-clamped via tanh (lines 104-109)
  - gWindTimeScale has a max of 0.5f (WrapperBase.cpp:205), and at 60fps fDeltaTime ~= 0.0167,
    giving fWindTimeScale ~= 0.5 at max settings -- well within stable range
  - The simulation is fundamentally stable by design: advection is semi-Lagrangian (unconditionally
    stable for any CFL), diffusion uses mix() which is bounded, decay uses pow() which is bounded
  Adding a CFL check would be adding validation (prohibited by CLAUDE.md) for a problem that
  cannot occur given the existing parameter bounds and algorithmic choices. REJECT.


Implementation Plan
-------------------

Step 1: Change default MSAA to 4x
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
File: Engine/Source/Ui/WrapperBase.cpp:9

Change the default value of gSampleCount from VK_SAMPLE_COUNT_2_BIT to VK_SAMPLE_COUNT_4_BIT.

Before:
  Wrapper gSampleCount(VK_SAMPLE_COUNT_2_BIT, std::move(std::vector<VkSampleCountFlagBits> {VK_SAMPLE_COUNT_2_BIT, VK_SAMPLE_COUNT_4_BIT, ...}));

After:
  Wrapper gSampleCount(VK_SAMPLE_COUNT_4_BIT, std::move(std::vector<VkSampleCountFlagBits> {VK_SAMPLE_COUNT_2_BIT, VK_SAMPLE_COUNT_4_BIT, ...}));

Only the first constructor argument changes. The allowed values list stays the same.


Step 2: Separable two-pass shadow blur
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Replace the single-pass 11x11 2D Gaussian blur with two passes: horizontal then vertical.
This reduces texture reads from 121 per texel to 22 per texel.

Step 2a: Create horizontal blur shader
File: Engine/Data/Shaders/Shadow/ShadowBlurH.comp (NEW)

  - Copy ShadowBlur.comp as starting point
  - Remove the 2D kernel; use a 1D horizontal kernel of width 11
  - For each texel (x, y): read 11 horizontal neighbors, multiply by 1D Gaussian weights, store result
  - Use the same sliding-window optimization as current shader but only in the X direction
  - Input: shadowTextureSampler (mShadowTexture)
  - Output: shadowBlurTexture (mShadowBlurTexture) -- this becomes the intermediate texture

Step 2b: Create vertical blur shader
File: Engine/Data/Shaders/Shadow/ShadowBlurV.comp (NEW)

  - Same structure as ShadowBlurH.comp but reads vertical neighbors
  - Dispatch with local_size_x = kiShadowTextureExecutionSize, local_size_y = 1
    (transposed from horizontal pass)
  - Input: shadowBlurTextureSampler (mShadowBlurTexture) -- reads horizontal pass output
  - Output: a storage image for final blurred result

Step 2c: Add a second shadow blur render target texture
File: Engine/Source/Graphics/Managers/TextureManager.h
File: Engine/Source/Graphics/Managers/RenderTargetTextures.cpp (or wherever mShadowBlurTexture is created)

  - Add mShadowBlurTextureV (or rename existing textures for clarity: mShadowBlurHTexture, mShadowBlurVTexture)
  - The horizontal pass writes to one texture, the vertical pass reads that and writes to the final output
  - The final blurred texture must be the one sampled by downstream consumers (terrain, objects)

Step 2d: Register both pipelines in PipelineManager
File: Engine/Source/Graphics/Managers/PipelineManager.cpp:237-248

  Replace the single kPipelineShadowBlur pipeline with two:
  - kPipelineShadowBlurH: reads mShadowTexture, writes mShadowBlurTexture (intermediate)
  - kPipelineShadowBlurV: reads mShadowBlurTexture, writes mShadowBlurVTexture (final)

  Add the new pipeline enum values to the pipeline enum (likely in PipelineManager.h or a shared header).

Step 2e: Update command buffer recording
File: Engine/Source/Graphics/Managers/CommandBufferManager.cpp (or wherever shadow blur dispatch occurs)

  - Dispatch kPipelineShadowBlurH
  - Insert a memory barrier (compute write -> compute read) between passes
  - Dispatch kPipelineShadowBlurV

Step 2f: Update all downstream consumers
  - Find all references to mShadowBlurTexture used as a sampled input
  - Point them to the new final output texture (mShadowBlurVTexture or equivalent)

Step 2g: Remove old ShadowBlur.comp
File: Engine/Data/Shaders/Shadow/ShadowBlur.comp (DELETE)


Step 3: Alpha-aware shadow casting for transparent materials
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Step 3a: Create alpha-tested shadow fragment shader
File: Engine/Data/Shaders/Model/ModelShadowAlpha.frag (NEW)

  - Based on ModelShadow.frag
  - Sample the color texture using the material's color texture index and UV set
  - If alpha < threshold (e.g., 0.5), discard the fragment
  - Otherwise output 0.0f as before (binary shadow, not modulated)
  - This requires the same descriptor bindings as the main Model.frag for texture access

Step 3b: Add shader CRC for the new shader
  - The DataPacker will generate the CRC automatically when the shader is added
  - Reference it as data::kShadersModelModelShadowAlphafragCrc

Step 3c: Modify DynamicPipelines to select shadow shader based on material transparency
File: Engine/Source/Graphics/Managers/DynamicPipelines.cpp:90-100

  - When creating a shadow pipeline, check if the material has transparency (alpha < 1.0 or has
    an alpha texture)
  - If transparent: use ModelShadowAlpha.frag instead of ModelShadow.frag
  - If opaque: continue using ModelShadow.frag (no performance penalty for opaque objects)
  - The transparent shadow pipeline needs the texture descriptor set bound (Set 0 global bindless
    textures are already available; Set 2 material descriptors need to be added)

Step 3d: Update pipeline descriptor layout for alpha shadow pipeline
  - The alpha shadow pipeline needs access to the bindless texture array (already in Set 0)
  - It also needs the material push constants or storage buffer to know which texture to sample
  - Since bAddModelDescriptors is already true, the material data should already be accessible
  - Verify that the shadow render pass supports the additional descriptor bindings
