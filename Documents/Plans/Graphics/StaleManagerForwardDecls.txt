Sweep Stale Forward Declarations in Graphics Managers
======================================================

Context
-------
While trimming `Engine/Source/Graphics/Managers/CommandBufferManager.h` during the
CommandBufferManager.cpp split (proud-jumping-candle plan), one orphan forward
declaration was found and removed: `struct RenderFrame;` on the old line 6 of
`CommandBufferManager.h`. It had no consumers in the trimmed header or its `.cpp`
and was a leftover from when recording methods that referenced `RenderFrame` lived
in this class. The session audit also flagged `BufferManager.h:7` as a probable
similar case but did not verify it.

Forward declarations rot quietly: a method that took `RenderFrame*` is removed,
the symbol stays declared in the header, and nothing breaks the build because
the declaration itself is harmless. Over time this accumulates noise that
misleads readers about the header's actual dependency surface.

Why
---
- Headers that declare types they don't use mislead readers about coupling.
- The fix is purely deletions of unused declarations — zero behavioural change,
  zero binary impact.
- One concrete case (`CommandBufferManager.h` `RenderFrame`) is already verified;
  the sibling pattern strongly suggests more cases exist.

Scope
-----
`Engine/Source/Graphics/Managers/*.h` only. Do not extend the sweep beyond this
directory in the same pass — keep the change contained to one folder so the
review surface is small.

Files to audit
--------------
All `.h` files under `Engine/Source/Graphics/Managers/`:
- `BufferManager.h` (audit explicitly flagged line 7 as a probable case)
- `CommandBufferManager.h` (already cleaned in proud-jumping-candle — re-verify only)
- `DeviceManager.h`
- `DynamicPipelines.h`
- `ImGuiManager.h`
- `InstanceManager.h`
- `ParticleManager.h`
- `PipelineManager.h`
- `RenderTargetTextures.h`
- `SwapchainManager.h`
- `TextManager.h`
- `TextureCache.h`
- `TextureDescriptors.h`
- `TextureManager.h`
- `TextureUploadManager.h`

Procedure
---------
For each header above:

1. Identify every forward-declared class/struct (top-of-file declarations of
   the form `class Foo;` or `struct Foo;` inside `namespace engine`).
2. For each declared symbol, grep both the header itself and its paired `.cpp`
   for any reference. If the symbol appears nowhere in either file, the
   declaration is dead.
3. Delete the dead declaration. Where multiple consecutive dead lines collapse,
   also delete the resulting blank-line run if the surrounding style otherwise
   has no blank line.
4. Build client + server (`/compile`) to confirm nothing in the broader engine
   depended on the header transitively re-declaring those symbols.

Verification
------------
- `/compile BrokenEngineSandbox` succeeds for both client (Debug) and server (Debug).
- `git diff --stat` shows only `.h` files modified, only line deletions, no
  added lines.
- Spot-check one or two surviving forward decls per file to confirm they are
  still used (so the sweep didn't accidentally delete a live one).

Estimated impact
----------------
- Effort: 1 (mechanical grep + delete; ~15 headers, a few minutes each).
- Impact: 1 (header-cleanliness, dependency clarity).
- Risks:  0 (pure deletion of demonstrably unused declarations).
- Score:  0.

Out of scope
------------
- Forward declarations outside `Engine/Source/Graphics/Managers/`.
- Replacing forward decls with full includes where a forward decl would suffice
  but a full include is currently used (separate concern).
- Reorganising header include order or namespace structure.
