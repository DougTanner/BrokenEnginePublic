HDR Resolve with ACES Tone Mapping and Color Grading
=====================================================

Context
-------
The engine currently renders the main scene pass (terrain, water, models,
particles, billboards, text) directly into the B8G8R8A8_UNORM swapchain
framebuffer. PBR lighting in Model.frag produces HDR values above 1.0 which
are silently clamped by the UNORM format. ACES tone mapping code exists as
dead code in Model.frag (lines 102-117: ACESFilm, Tonemap, TonemapIBL) but
is only applied to IBL cubemap samples, never to the final scene output.
There is no post-process resolve pass.

Why
---
- HDR values from PBR lighting, emissive materials, and additive particles
  are clamped to 1.0 by the UNORM framebuffer, losing highlight detail
- Tone mapping must happen as a fullscreen post-process on the accumulated
  HDR scene, not per-material (current approach clips before blending)
- A dedicated resolve pass enables color grading (saturation, contrast,
  temperature) without touching every material shader
- The existing ACESFilm code in Model.frag can be moved to the resolve
  shader and removed from per-material tone mapping

7. Engine/Data/Shaders/HdrResolve.frag (NEW FILE)
   Fullscreen resolve fragment shader with ACES tone mapping and color
   grading. Samples the F16 HDR texture, applies exposure, ACES tone
   mapping, color grading (saturation, contrast, color temperature), and
   gamma correction:

     #version 460
     #include "ShaderLayouts.h"
     #include "ShaderFunctions.h"

     layout (set = 0, binding = 0) uniform globalUniform { GlobalLayout globalLayout; };
     layout (set = 0, binding = 1) uniform mainUniform { MainLayout mainLayout; };
     layout (set = 1, binding = 2) uniform sampler2D hdrSampler;

     layout (location = 0) in flat int iInInstanceIndex;
     layout (location = 1) in vec2 f2InTexcoord;
     layout (location = 0) out vec4 f4OutColor;

     vec3 ACESFilm(vec3 x)
     {
         const float a = 2.51;
         const float b = 0.03;
         const float c = 2.43;
         const float d = 0.59;
         const float e = 0.14;
         return clamp((x * (a * x + b)) / (x * (c * x + d) + e), 0.0, 1.0);
     }

     void main()
     {
         vec3 hdr = texture(hdrSampler, f2InTexcoord).rgb;

         // Exposure
         hdr *= mainLayout.fPbrExposure;

         // ACES tone mapping
         vec3 mapped = ACESFilm(hdr);

         // Color grading: saturation
         float luminance = dot(mapped, vec3(0.2126, 0.7152, 0.0722));
         mapped = mix(vec3(luminance), mapped, mainLayout.fColorGradingSaturation);

         // Color grading: contrast (around mid-gray 0.18)
         mapped = pow(mapped / 0.18, vec3(mainLayout.fColorGradingContrast)) * 0.18;
         mapped = clamp(mapped, 0.0, 1.0);

         // Color grading: temperature shift (warm positive, cool negative)
         float temp = mainLayout.fColorGradingTemperature;
         mapped.r *= 1.0 + temp * 0.1;
         mapped.b *= 1.0 - temp * 0.1;
         mapped = clamp(mapped, 0.0, 1.0);

         // Gamma correction
         mapped = pow(mapped, vec3(1.0 / mainLayout.fPbrGamma));

         f4OutColor = vec4(mapped, 1.0);
     }

Notes
-----
- The HDR framebuffer uses R16G16B16A16_SFLOAT (F16), not F32, for
  bandwidth efficiency. F16 provides sufficient range (65504 max) for
  scene HDR values
- All pipelines that currently default to gpSwapchainManager->mVkRenderPass
  (terrain, water, models, particles, billboards, hex shields, profile
  text) will automatically target the HDR render pass via the
  PipelineCreator.cpp change. Only the HdrResolve pipeline explicitly
  targets the swapchain render pass
- The resolve pass runs after the image render pass ends, so the HDR
  texture transitions to SHADER_READ_ONLY_OPTIMAL (via the render pass
  finalLayout) before sampling
- Profile text renders into the HDR buffer. If text readability suffers
  from tone mapping, a follow-up change can move text rendering to after
  the resolve pass (into the swapchain pass)
- Screenshot captures from the swapchain image (post-resolve), so
  screenshots will include tone mapping and color grading
- The color grading parameters (saturation, contrast, temperature) are
  intentionally simple. A LUT-based approach can be added later without
  changing the pipeline architecture
- DataPacker must be re-run to compile the new HdrResolve.frag shader
  and generate its CRC constant (data::kShadersHdrResolvefragCrc)
