# Features

Plans for work that adds a capability the engine does not already have. Feature plans are tracked Markdown documents, but execution is manual: WorktreeCli never validates, claims, stores locks for, or changes `Documents/Features`.

Use existing subject-area subdirectories and retain clear scope, invariants, and acceptance criteria. If work is a refactor or bugfix rather than a new capability, place it in `Documents/Plans`, the only tree covered by `/next-plan`.

A design deferred because it is not needed yet keeps a `Revisit When` line naming the concrete trigger that would make it worth doing, so a later reader can tell a rejected idea from a waiting one. The `Frame/Future_*.txt` documents are the pattern.
