Use the following rules for C++ code

1. Use tabs for indentation	

2. Curly braces go on the next line for functions, scopes, and lambdas. Struct or class initializers can have curly braces on the same line.

	if ()
	{
	}

	auto GetContent = [](const auto& rSource) -> std::pair<bool, std::string>
	{
	}

3. Hungarian notation

	Constexpr - k
	Enum declaration - k

	Static - s

	Global - g
	Member of a class - m (classes only, not structs)

	Pointer - p
	Reference - r

	character - c
	integer - i
	unsigned integer, unsigned short, byte - ui
	boolean - b
	enum variable - e
	float, double - f
	XMFLOAT[2/3/4] - [f2/f3/f4]
	XMVector - vec
	XMMatrix - mat

	std::string and std::string_view - no hungarian prefix
	
4. Use "#pragma once" for header guards

5. Use RAII for allocations and locking

6. When turning features on and off with preprocessors, use ENABLE_* defines. Avoid using configuration differences directly (BT_DEBUG vs. BT_RELEASE)

7. Camel case, except for preprocessor macros and template parameters. Classes and functions start with an uppercase letter, variables start with a lowercase letter.

	class RenderThread
	constexpr uint32_t kuiThreadCount
	#define ENABLE_LOGGING
	template <typename T> or template <typename... TUV>

8. Use i/j/k variable names in for loops, but prefer range-based for loop when possible. If a counter variable is required with a range-based for loop, use the C++20 syntax to include include an initializer statement. Use "it" for iterators.

9. Exceptions for fatal errors only (things that would cause the program to crash), not control flow

10. "/" for header include paths, not "\\"

11. Use C++-style casts, static_cast reinterpret_cast etc...

12. For duration and time use std::chorono, use chrono_literals suffixes for example:
	Nanoseconds - std::chorono::nanoseconds durationNanoseconds = 10ns;
	Microseconds - us
	Milliseconds - ms
	Seconds - std::chorono::seconds seekSeconds = 1s;

13. Default to int64_t
    -Use int8_t, int16_t when packing into structs and arrays (if higher range of larger types is not required)
	-Use unsigned integers when doing bitwise operations
	-Use the corresponding type when dealing with directly with parameters and return values from other APIs (ex: Vulkan uses uint32_t)

14. Use "Count" not "Num", ex: uint32_t kuiThreadCount = 3; not kuiNumThreads

15. YOU MUST not use auto keyword unless:
	a) It's an XMVECTOR or XMMATRIX: use auto for results of "DirectX Math" functions
	b) The type is obvious from a template parameter to the right
	c) It is an iterator
	d) It is a structured binding
	
IMPORTANT do not use auto in range-based for loops

16. Access std::vectors and std::maps with .at()

17. Use size_t for std::vector sizes and indices

18. Use "const" if:
	a) A pointer or reference is passed into a function and not modified
	b) A reference in a ranged for loop is not modified

19. Use "typename" not "class" for template declarations, template parameters should be in all upper case ex: template <typename T, typename... TUV>

20. Use uniform initialization only for structures, arrays, and initializer list constructed classes
	int i = 0;
	Class class(0, i);
	Struct struct {a = 0, b = i};

21. Don't use std::array or std::span because operator[] is slow in debug. Except when storing pointer + size for mapped Vulkan memory.

22. Have a comma at the end of every line in initializer lists

	int pInts[] =
	{
		1,
		2,
	};

23. Use 'using' keyword instead of typedefs

24. Normalized XMVECTORs should be postfixed with "Normal", a postfix of "Direction" also implies that it is normalized

25. Use "static constexpr" at function scope, "inline constexpr" at global scope in headers

26. Avoid overuse of "using enum", try to only use on enums in direct header

27. Floating point constants should always have the decimal and first digit, even if it's 0, and should have 'f' appended

28. Use nullptr instead of NULL

29. Use override keyword on child class virtual functions

30. No space on ">>" ex: std::vector<std::vector<float>>

31. Use static_assert instead of runtime assert whenever possible

32. Use std::unordered_map instead of std::map

33. Do not use any constants from limits.h, instead use std::numeric_limits

34. Use digit separators for large numbers: uint32_t uiOneMillion = 1'000'000;

35. Use the file system library std::filesystem

36. Always initialize variables (unless it is a class with a constructor). Use inline variables with initializers in header (both globals and class members). Do not initalize class member variables in the .cpp file.

37. Use structured bindings for multiple return from functions with std::tuple<>: auto [a, b, c] = getThreeReturnValues();

38. Use structured bindings in range-based for loops over associative containers (std::map, std::unordered_map)

	for (const auto& [rCrc, rTexture] : mTextureMap)
	{
		crcs.push_back(rTexture.mInfo.crc);
	}

39. Use [[maybe_unused]] when a variable is unused

40. Use std::string_view or std::wstring_view instead of "const char*" or std::string& or std::wstring& parameters into functions

41. Explicitly use std:: namespace, do not `using namespace std;`
NOTE: The following global namespaces are allowed: `using namespace DirectX;`

42. Use designated initializers for struct initializers

43. Run-Time Type Info (RTTI) is disabled, do not use it

44. Do not use std::bitset due to bad performance

45. Prefer aligned data for "DirectX Math": XMStoreFloat4A is better than XMStoreFloat4

46. Do not use Est (estimate) functions in "DirectX Math", they may have different behaviour on different architectures: Use XMVectorReciprocal(), not XMVectorReciprocalEst()

47. Header includes should be sorted alphabetically (only within the same grouping)

48. Don't add extra curly brackets for scope to force close std::fstream, instead use .close() when no longer needed

49. Don't use getters and setters to access class members, make the members public instead

50. if () statements compare booleans they don't take pointers:

	if (pPointer != nullptr)
	{
	}

51. Keep function parameters all on the same line, even if it would be a very long line. The only exception would be passing in lambdas or structs in which case next-line {} placement takes priority.
